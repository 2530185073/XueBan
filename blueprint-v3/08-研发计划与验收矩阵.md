# 08 研发计划与验收矩阵

版本：v3.0 · 2026-10-16。本文将完整 v1 拆为可排期、可验收的工程工作。下列时长、样本和阈值均为项目建议值，不是已测结果或交付承诺；启动时冻结适用范围和验收口径，变更后重新评估。

## 1 完整 v1 的交付边界

完整 v1 包含：每生个人知识图谱、长期专属智能体、纠错诊断、举一反三、独立下一课预习、错题及半月小测、家长报告；同时包含学科老师复核、线下教官习惯观察及干预、校区共性问题研判、家长沟通回访和必要的数据治理。不能只上线拍照判题就称为完成 v1。

完整指功能和服务流程完整，不代表首发支持所有年级、教材和题型。首发内容包必须明确学校/年级/教材/学科/章节/题型；未覆盖内容显示人工处理或未支持，不生成假分析。初次建议一个年级、一种教材、一个主学科验证完整链路；多机构数据隔离必须从 v1 建立，但跨机构经营分析与全量历史迁移不在首发范围。

| 交付物 | 完成定义 |
|---|---|
| 学生端 | 采集、订正、分层提示、练习、个人图谱、预习、小测、计划及进步记录可用 |
| 学科老师端 | 复核、诊断、图谱证据检查、内容审核、教学任务与试卷确认、报告确认可用 |
| 教官端 | 观察事实、习惯目标、干预执行、回看验证、交接可用；学科权限隔离 |
| 家长端 | 已发布报告、证据摘要、下期计划、反馈及异议跟进可用 |
| 校区端 | 错题汇总、共性研判、任务分派、到期积压、沟通和复核容量可用 |
| 基础服务 | 真实鉴权、持久存储、异步任务、审计、恢复、纠错传播、导出与删除流程通过验收 |
| 内容与运营包 | 有来源的首发内容、教师金标准集、岗位 SOP、培训和异常处理演练记录 |

图谱动画、虚拟形象、积分商城、自由网页浏览、无限开放聊天、自研设备管理、所有学科内容、基础模型训练和模型完全私有部署独立估算，不挤占上述完整流程。

本包中的数据契约和可运行参考内核属于研发参考交付：PostgreSQL DDL 用于正式结构评审；参考服务用内存仓库和固定演示身份，展示隔离读取、老师确认、规则投影/撤销重算、计划、观察干预、预习及半月报告的关键机制。它不接真实 LLM 或学生数据，不等于生产后端、完整终端或上线安全已经完成。所有生产用户故事初始状态统一为 `not_started`（待开发），不得把演示子集的测试通过映射为任一 US 已完成。

## 2 排期成立的前提与责任人

建议工程配置为产品负责人 1、技术负责人兼后端 1、后端 1、前端 2、AI/评测工程师 1、QA 1，另配设计约 0.5、运维/安全约 0.5、学科教研至少 1 位持续投入。驻场老师、教官和校区负责人提供试运行时间，不能从研发人数推导其运营人力已经解决。

以下排期以团队熟悉所选技术栈、可使用合适的模型服务、内容首批可供审核、无大规模旧系统迁移、终端采用现有平板与 Web 页面为前提。若需要采购专机、重写原生设备层、全科内容或完全私有模型，应单独添加关键路径。供应商可用性、授权和数据处理安排未确认时，开发用合成样本和适配器桩继续进行，真实数据联调暂停。

角色简称：PO 产品负责人；TL 技术负责人；BE 后端；FE 前端；AI 模型与评测；QA 测试；CUR 教研；ST 学科老师；CO 教官；OPS 运维/安全；PM 校区负责人。每项只设一个验收主责，其余为协作方。

## 3 8—12 周的条件化工程计划

建议基线为 12 周：前 8 周完成候选版本与内部全流程演练，后约一个自然月进行两个半月周期的受控运行和修正。只有已有基础设施、内容及团队熟练时，8 周才可能交付可进入试点的候选版本；8 周不包含尚未发生的长期效果验证。半月固定按 Asia/Shanghai 时区的自然月 1—15 日、16 日—月末划分；查询使用左闭右开区间（1 日 00:00 至 16 日 00:00；16 日 00:00 至下月 1 日 00:00）。W9—12 是排期近似，若启动日不在周期边界、跨假期或出勤不足，需要延长至两个完整周期结束。

| 阶段 | 主责与协作 | 工作及依赖 | 阶段退出证据 |
|---|---|---|---|
| W1 需求和契约冻结 | PO；TL/CUR/PM | 冻结首发内容、角色、页面流、状态和错误码；定稿数据契约与指标 | 学生、学科老师、教官、家长、校区负责人五类角色走查；关键流程及至少一份完整学生案例签收 |
| W1—2 工程与内容底座 | TL；BE/OPS/QA/CUR | 真实身份、租户与学生授权、数据库迁移、对象存储、审计、内容版本、金标准集；依赖契约 | 空库部署成功；跨学生/租户负向检查通过；首批题有人工标准 |
| W2—4 采集与确认 | BE；FE/AI/ST/QA | 上传、切题候选、初判、复核、申诉、可靠任务、误判重算；依赖底座 | 真实终端跑通一题闭环及失败恢复；错误不会未经确认进入图谱 |
| W3—5 个人图谱与教官链路 | TL；BE/FE/CUR/CO | 规则投影、前置关系、证据详情、观察/自述区分、习惯干预、版本修正 | 同输入同规则可重算；教官不能改学科结论；干预有负责人和验证 |
| W4—6 个人智能体 | AI；BE/FE/CUR/QA | 身份和记忆、上下文包、工具、预算、提示模式、人审、供应商适配 | 两个学生相同提问能引用各自证据；没有跨生读取或直接写掌握度 |
| W5—7 学习任务与预习 | FE；BE/AI/CUR/ST | 举一反三、任务预算、独立预习、真实课序、课后回流；依赖图谱及题库 | 同下一课生成不同前置任务；课程变化使旧草案失效 |
| W6—8 小测、报告与校区研判 | BE；FE/AI/ST/PM | 半月周期、试卷确认、缺测、锁定快照、报告发布、沟通回访、共性统计 | 一组虚构学生完整跨两周期演练；所有统计能追溯到分母及证据 |
| W7—8 发布候选与演练 | QA；全员 | 回归、负载、注入、离线、恢复、删除、权限撤回、培训；依赖全流程 | G1 技术门槛全部通过；发布/回滚及运营负责人就绪 |
| W9—10 受控试点周期一 | PM；ST/CO/QA/AI | 10—20 名获适当授权学生；全量学科确认；记工时与学生负担 | 完成第一轮目标—任务—复测—报告；缺测和失败单独统计 |
| W11—12 试点周期二与发布评审 | PO；PM/QA/TL/CUR | 针对真实缺陷迭代，保留变更记录和可比题；执行 G2/G3 | 两个完整周期的证据、可接受的人力负荷、无未关闭发布阻断项 |

粗估工程量可按 50—70 人周评审，包含前后端、AI、QA、集成与发布；不包含驻场运营、全科内容生产或私有模型算力。该范围不应直接乘平均工资当报价：先按实际人员和内容准备度细化任务，再加显式预留。第二周若仍没有可审核内容或数据契约未稳定，应重排后续阶段，不靠省略验收追赶日期。

## 4 工作包与依赖清单

| 包 | 主责 | 前置包 | 可独立验收的产出 |
|---|---|---|---|
| P01 身份与数据底座 | TL | 无 | 授权、租户隔离、迁移、审计、对象访问、备份 |
| P02 课程和内容 | CUR | 内容范围冻结 | 课程关系、题库版本、讲解、评分规则、首批金标准 |
| P03 采集与复核 | BE | P01/P02 | 上传、初判、复核队列、订正、申诉、作答条件 |
| P04 个人图谱与证据 | TL | P01/P03 | 投影、规则版本、反例、撤销重算、变化记录 |
| P05 专属智能体 | AI | P01/P02/P04 | 独立状态、记忆、工具、上下文、模式、人工转接 |
| P06 练习与预习 | FE | P02/P04/P05 | 个性任务、负担预算、课序与前置检查、课后关联 |
| P07 教官干预与校区研判 | BE | P01/P03/P04 | 事实观察、临时分组、任务指派、回看和交接 |
| P08 半月测验与报告 | BE | P03/P04/P06/P07 | 组卷、实施、缺测、证据快照、报告与沟通 |
| P09 质量与运营保障 | QA | 贯穿 P01—P08 | 自动回归、人工抽检、恢复/删除/隔离演练、培训 |

P05 的适配器和工具桩可与 P04 并行开发，但真实图谱读取和证据失效验收必须在集成后完成。任何把学科人审、教官跟进或家长反馈当作“系统外人工，因此不必做状态”的实现均不满足完整 v1。

## 5 用户故事与验收矩阵

本表用于建立需求单与自动/人工测试用例的对应关系。每项必须记录实现提交、测试证据、执行人和日期；状态为 `not_started / in_progress / ready_for_qa / passed / blocked`。下表的状态词是业务行为要求，正式 API 枚举以契约为准，禁止前后端各自翻译出不同状态。

| ID | 用户故事与主责 | 正常路径及状态验收 | 错误与权限验收 |
|---|---|---|---|
| US-01 | 校区管理员创建学生及监护绑定；TL | 正确绑定后监护人可见该生已发布内容；绑定变更留审计 | 非绑定家长读取、枚举或导出学生资料均拒绝；撤销后缓存访问失效 |
| US-02 | 老师进入授权班级；TL | 教师只能查询授权范围，学生迁班后权限按新规则生效 | 修改 URL、请求体或缓存键不能跨学生/校区/机构；返回不泄露对象存在性 |
| US-03 | 学生上传作业；BE | 同一次上传重试只产生一次提交；页面显示 received/processing | 缺图、损坏、超限、伪装格式有明确错误；文件不可公开访问 |
| US-04 | 老师补正识别与切题；FE | 保存原图、题目边界及人工修订版本；后续分析读取新版 | 题干不完整进入 needs_resubmit，不自动编造缺少条件 |
| US-05 | 学生收到可靠纠错；AI | 初判进入 awaiting_review；老师 confirmed 后学生可用 | 模型超时/拒绝/截断保留失败原因；不得显示老师已确认 |
| US-06 | 学科老师采纳或改判；BE | 判定、错误步骤、解释及原因关联 review_decision | 教官、学生、家长和模型服务不能调用确认命令；旧版本提交返回 409 |
| US-07 | 学生申诉误判；BE | 申诉进入待处理，老师新决定替代旧判断，相关任务可追踪 | 旧证据被撤销后不得继续影响当前图谱或新报告；保留原作答 |
| US-08 | 学生完成订正；FE | 订正形成新 attempt，注明已用提示；原错误仍可回看 | 重复上传同一订正去重；不能把看答案后改对标为独立验证 |
| US-09 | 老师查看知识点诊断；CUR | 主/关联知识点和错因分别展示，结论可点击到证据 | 无作答过程时显示待核实；一次错误不能自动定性“粗心” |
| US-10 | 学生查看个人知识图谱；FE | 课程图谱叠加个人状态、样本量、日期、证据及下一步 | 未观察节点显示数据不足；不把全班平均值填成本人状态 |
| US-11 | 系统更新知识状态；TL | 已确认有效证据按版本规则计算；重放得到同一投影 | 待审核、被撤销、条件未核实证据不能越权触发高质量验证结果 |
| US-12 | 老师修正图谱或题目映射；TL | 新版本重算受影响状态，旧结果可追溯，待执行计划标 stale | 重算未完成时禁止用旧状态发布报告；重复事件不重复累计证据 |
| US-13 | 每个孩子保有专属智能体；AI | 重登/换设备后加载本人状态；模型升级后个人数据仍在 | 两生同时运行无会话、记忆、检索、工具或费用明细串用 |
| US-14 | 学生获得个性学习建议；AI | 同一问题按各自图谱、任务和证据生成不同且可解释的建议 | 缺少下一课或证据时 needs_evidence；不得虚构既往表现 |
| US-15 | 学生与老师确认长期记忆；BE | 候选→确认→到期/替代；保留来源、确认人和期限 | 学生不能确认学科诊断；模型不能把自述直接写为长期事实 |
| US-16 | 学生获取分层帮助；AI | 当前模式允许的提示逐级出现，提示层级写入 attempt 条件 | 测验模式禁提示工具；越级套答案、文档注入和多轮诱导被阻止或转人工 |
| US-17 | 智能体调用学习工具；AI | 工具只访问当前学生批准内容，并记录输入、结果和原因 | 未知工具、任意 SQL/URL、跨生 ID、超步数均拒绝；不直接改成绩 |
| US-18 | 老师接收智能体转介；BE | needs_human 形成具体责任队列；无老师时待安排并显示原因 | 转人工失败不得伪装已完成；未经接单不显示“老师正在处理” |
| US-19 | 学生做举一反三；CUR | 每组关联原错点，结构变化与迁移用途明确；老师可替换 | 未审核生成题不可投放；连续失败转讲解而非无限加题 |
| US-20 | 学生按负担预算完成任务；FE | 当天纠错/复习/预习共享预算，超预算建议可延期 | 取消/替换任务有原因；智能体不能绕过预算重复创建同目标任务 |
| US-21 | 老师维护学校课程进度；BE | 进度有学校/教材/学科/确认人/时间，下一课据此确定 | 未确认时不能按目录自动认定下一课；旧版本并发更新受冲突检查 |
| US-22 | 学生进入独立预习板块；FE | 显示目标、前置检查、个人缺口、短导学和上课关注点 | 进度修改后旧草案失效；新课未学会不直接记为已学知识退步 |
| US-23 | 老师查看课前课后关联；BE | 预习记录可关联课后独立作答，展示条件和时间 | 只有缺勤或未采集时标缺失，不能记作预习失败或宣称因果提分 |
| US-24 | 学生使用错题本；FE | 支持状态、知识点、错因、时间筛选及打印；历史保留 | 误判撤销从有效错题统计剔除；重复照片不增加错误次数 |
| US-25 | 老师创建半月测验；CUR | 周期、目标和通过标准测前冻结，候选卷审核后可实施 | 已直接练过的题不能充当新题迁移证据；有题目冲突时阻止发布 |
| US-26 | 学生独立参加小测；FE | 测验模式锁定提示；分题结果与条件保存，缺席进入待补测 | 掉线恢复不重复作答；无法核实独立条件时标记条件未核实 |
| US-27 | 老师复盘半月目标；BE | 显示目标总数、已覆盖目标、达标目标和缺测目标，回写下期计划 | 缺测不算达标；不同难度个性卷总分不得直接排名或比较涨幅 |
| US-28 | 教官记录学习观察；FE | 分开记录事实、学生自述、推测；有时间/场景/观察者 | 不允许自动识别情绪或诊断心理；观察不能修改学科掌握分 |
| US-29 | 教官执行习惯干预；BE | 目标、具体行为、责任人、期限、执行与回看结果齐全 | “已提醒”不等于验证成功；撤销或改计划有理由且保留记录 |
| US-30 | 老师和教官交接；FE | 学科困难转老师，执行困难转教官；待接/处理中/已回执可追踪 | 转介只附必要数据；未获学科权限的教官不能查看或修改评分操作 |
| US-31 | 校区查看共性问题；BE | 同题/知识点/错因聚合，显示有效作答分母、人数与采集覆盖 | 只采错题时不展示知识点错误率；订正和初作不混作一次分母 |
| US-32 | 校区安排个别或小组补学；BE | 研判单转 intervention，人员、内容、时间、验证明确 | 分组随证据调整；家长看不到其他学生名单或原始作答 |
| US-33 | 老师确认家长报告；FE | 报告用锁定证据与数字，学科/习惯分别确认后可发布 | 缺确认、投影落后、证据撤销或数值不一致时阻止发布 |
| US-34 | 家长收到报告及后续计划；BE | 发送命令有幂等键、回执和发布版本；本人历史可查 | 网络超时不能盲目重复发送；更正生成新版并提示旧版已更新 |
| US-35 | 家长反馈与线下面谈跟进；FE | 反馈转负责人待办，记录约定、行动和回看时间 | 无负责人不得显示已处理；新增收费内容与教学建议区分并单独确认 |
| US-36 | 校区应对模型或网络故障；OPS | 已确认任务仍可用，新分析排队或转人工；失败有状态 | 不将服务失败计为学生不配合；重试不重复生成任务或费用业务记录 |
| US-37 | 工作人员撤回或删除资料；BE | 删除传播到对象/索引/摘要/缓存，保留最少审计与执行回执 | 未核验身份不能执行；恢复备份必须重放删除清单，防止复活 |
| US-38 | 研发安全发布模型版本；AI | 锁定评测集回归、影子、灰度、版本记录和回滚均可执行 | 关键切片退化/越权/泄漏阻止放量；不以总体均分掩盖切片失败 |
| US-39 | 运维恢复任务与数据；OPS | Worker 中断、租约失效、服务重启、备份恢复后任务可续办 | 重复投递不重复更新掌握状态；人工确认不被模型重试覆盖 |
| US-40 | 负责人评估服务效果与工时；PO | 分开展示学习、执行、质量、教师负担与学生负担 | 采纳率不等于准确率，打开率不等于满意，相关变化不写因果提分 |

## 6 状态、错误码与测试夹具

任何用户故事至少覆盖成功、缺数据、无权限、并发修改和外部失败中适用的分支。命令统一返回 `request_id`，异步命令另返回任务编号与可查询状态。HTTP 与业务错误建议固定如下，正式枚举随契约版本冻结。

| 类别 | 建议错误 | 客户端行为 |
|---|---|---|
| 未登录 | 401 AUTH_REQUIRED | 暂停上传/写操作，引导重新认证 |
| 没有角色权限 | 403 FORBIDDEN | 说明该操作需要对应岗位，不提供越权按钮 |
| 对象不在可访问范围 | 404 NOT_FOUND | 不暴露其他学生或机构对象是否存在 |
| 并发或过期上下文 | 409 VERSION_CONFLICT / STALE_CONTEXT | 重新读取，展示新旧差异，不自动覆盖老师变更 |
| 业务状态不允许 | 409 INVALID_TRANSITION | 显示当前状态及合法下一步 |
| 输入或证据不满足 | 422 INVALID_INPUT / INSUFFICIENT_EVIDENCE | 指明可修正项或待补证据 |
| 调用配额/负担预算 | 429 RATE_LIMITED / BUDGET_EXCEEDED | 排队、延期或转人工，不自动重复请求 |
| 模型/依赖异常 | 503 DEPENDENCY_UNAVAILABLE | 保持已有任务可用，展示重试或人工处理状态 |

测试夹具至少包含：两机构各两校区、不同授权班级、两名有相似姓名但不同身份的学生、一个跨校区转入学生、一名已撤销绑定家长、教官/学科老师双角色人员。证据样本含正确作答、等价答案、错误过程、部分正确、无过程、看过答案、缺测、条件未核实、撤销误判、教材进度变更及重复事件。

跨学生和跨租户测试必须覆盖 API、数据库会话、Worker、对象下载、搜索、向量检索、缓存、导出和报告链接。不能只测页面菜单是否隐藏。RLS 需用生产等价非特权数据库账号验证，不能用超级用户测试后认定安全。

## 7 三道发布门槛

### G1：可以带真实学生受控试点

硬门槛全部满足才进入受控试点；数值是建议验收目标，启动时可基于范围重定，但不可在失败后悄悄更换分母。

| 门槛 | 建议验收方法与通过条件 |
|---|---|
| 身份隔离与权限 | 预先列出的全部跨生/租户负向用例零泄漏、零越权写；任一失败即阻断 |
| 证据及状态 | US-06/07/11/12/27/33/39 的确定性用例全部通过；重放与撤销重算结果一致 |
| 内容正确性 | 每个上线题型至少 30 个独立金标准样本、总体至少 200 个；含典型错误及低质量输入；按切片记录初判与教师确认后结果，不只报总体准确率 |
| 学科发布 | 首发全量老师确认；金标准上有严重错误解释、错误答案或错误推荐流出时阻断相关能力，修复后复验 |
| 智能体约束 | 固定注入/跨生/测验套答案测试中零成功越权及泄漏；工具预算、拒绝、截断和超时路径全部通过；不宣称由此证明所有攻击均安全 |
| 引用与报告 | 测试报告所有数字由程序计算且可回溯；事实性个人判断必须有有效证据或显式待核实；无证据捏造阻断 |
| 可靠性 | 断网、重复投递、Worker 崩溃和模型失败演练无已确认作答丢失、无重复业务副作用；待处理记录可查 |
| 数据流程 | 真实数据使用范围、主体授权、供应商安排、留存及退出流程落实；普通开发环境不使用真实学生数据 |
| 运营能力 | 老师、教官、负责人均完成培训；排班缺口、任务积压和投诉有承接人；准备纸笔/人工降级路径 |

AI 初判效率单独观察：一键采纳率按有效复核题计算，改判原因按识别/判定/知识点/解释等分开。初判不达期望时可以继续受控人工试点，但不能释放未确认结果或宣称自动批改已达标。外部模型基准成绩不替代本项目测试。

### G2：完整 v1 试点验收

至少完成连续两个半月服务周期，建议 10—20 名学生。每个周期固定目标、必要题型、作答条件和适用的达标标准；缺席及转人工如实记录，不因未完成而从样本静默删除。

| 验收维度 | 计算口径和通过判断 |
|---|---|
| 功能完整 | US-01—40 中适用于首发范围的项目全部有证据；明确不适用须 PO 与 QA 联合说明，不能据此豁免核心模块 |
| 服务完成 | 到期任务中已按计划处理数/到期任务数；复测覆盖用已有效复测目标数/应复测目标数；报告按时率用按时发布份数/应发布份数；目标建议均≥90%，缺测及取消另列 |
| 学习证据 | 按学生列目标总数、有效覆盖目标数、达标目标数；展示独立变式结果和复发情况。没有改善时须能说明证据并调整计划，不把提分当作软件验收承诺 |
| 个性化 | 至少 5 组同课不同薄弱点案例，老师能确认预习/练习任务差异有依据；同一学生跨周期能体现新证据与记忆修正 |
| 人力容量 | 实测复核、讲解、内容确认、习惯记录和沟通总时间不超过排班可用时间；连续积压需降任务量或增人，不能靠隐性加班算通过 |
| 学生负担 | 记录额外任务用时与未完成原因；超过已批准预算必须有调整记录；不得通过强迫超时完成美化完成率 |
| 家长可理解性 | 抽样回访能说清当前问题、证据及下步安排；反馈有处理回执；只打开报告不等于理解 |

90% 是服务试点建议目标，不适用于鉴权、证据造假或严重内容错误等硬门槛。必须同时展示人数和分母；例如 9/10 与 90/100 不能当成同等确定的长期结果。

### G3：可扩大日常运营

必须满足 G1/G2，关闭所有阻断项，并具备生产发布、回滚、备份恢复和应急值班记录。关键的模型/题型覆盖和老师容量须随扩大范围重新验收；不能把一个班数学通过视为多校区全学科通过。

性能基线建议在声明场景下测试：例如 100 名同时在线、20 份作业在 5 分钟内提交。普通列表读取建议 p95≤1 秒，上传确认 p95≤2 秒，模型处理进度必须可见；AI 完成耗时另报 p50/p95，不能包含老师等候时间后仍称纯模型延迟。数字是起始 SLO，不是当前性能。上传确认只代表元数据和完整性确认，不承诺两秒传完大图。

建议恢复目标 RPO≤24 小时、RTO≤4 小时作为首发讨论起点，生产负责人须按业务容忍度签收并演练。持久数据库恢复窗口内仍可能损失未备份数据；若业务要求更低 RPO，需配置相应增量日志和恢复机制，不能以 Worker 幂等代替备份。

## 8 缺陷、回滚与范围变更

P0：跨学生泄漏、未授权写、严重不当内容外发、不可恢复的数据损失。立即停止受影响功能，保留最小必要证据，人工承接并启动修复。P1：误判未撤回、图谱状态错误、测验泄题、报告数字错误、核心流程无法继续。不得带入扩大运营。P2：有可靠人工替代的局部问题，可记录负责人和期限后继续受控试点；不能重复展期而无修复。

模型切换先冻结新调用或退回上一已验证路由，业务数据不随模型回滚而删除。数据库采用向前兼容迁移；已执行迁移的回退需专门方案，不能仅回滚应用镜像。内容版本和规则版本独立发布，历史结果保留原版本标识。

任何扩科、增加年级、增加数据来源、开放新工具或改变独立验证规则，都提交变更单：目的、影响用户、内容/权限/数据影响、研发量、评测样本和回滚条件。由 PO 负责范围，CUR 负责教学正确性，TL/OPS 负责系统及数据，PM 负责实际人力。

## 9 发布交接包

最终交接必须包括：发布版本和覆盖清单；数据契约与迁移；配置及密钥交接说明；内容来源和版本；锁定评测集与结果；US-01—40 验收记录；岗位操作手册；权限名册；备份恢复和删除演练；已知限制；异常联系人；模型与内容变更流程；试点报告及下一阶段范围。

评测持续进入发布流程。模型、提示词、图谱、评分规则、工具权限或检索策略变更，均按影响范围触发回归；真实改判与事故在去除不必要个人信息后回流测试集。任务特定评测和持续回归可参考 [OpenAI Evaluation best practices](https://developers.openai.com/api/docs/guides/evaluation-best-practices)，具体教学标准由本项目教研负责，而非由通用模型评分替代。
