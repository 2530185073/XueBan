# 08 研发计划与验收矩阵

版本：v3.2 · 2026-10-16。本文将完整 v1 拆为可排期、可验收的工程工作。下列时长、样本和阈值均为项目建议值，不是已测结果或交付承诺；启动时冻结适用范围和验收口径，变更后重新评估。

## 1 完整 v1 的交付边界

完整 v1 面向托管班：AI 优先辅助孩子自主完成学校课程与作业，以学校作业纠错为第一核心，个人知识图谱、专属智能体和家长报告围绕纠错证据展开。交付纠错与知识点分析、轻量举一反三选做、独立预习板块、错题整理、固定半月证据汇总及可选小测、家长报告；同时包含坐班老师现场答疑与作业证据确认、习惯支持、校区错题汇总研判、沟通回访和数据治理。完整交付这些能力，不代表每个孩子必须每天使用所有模块。

学校任务优先；`task_origin=school|optional`，`extra_minutes` 默认 0。只有学校任务完成、孩子愿意、有余力三项同时经服务端核实，并有明确额外预算，才允许轻量选做。暂停/跳过无惩罚、无欠账、无次日自动补做。学校布置的预习正常协助，不受“全部学校任务已完成”门禁；AI 不超学校进度自动加课，不为填图谱强制加题，不新设补课课程、小组补学或硬性测验。坐班老师只在能力范围答疑和确认证据，无把握保留待核实。

完整指功能和服务流程完整，不代表首发支持所有年级、教材和题型。首发内容包必须明确学校/年级/教材/学科/章节/题型；未覆盖内容显示人工处理或未支持，不生成假分析。初次建议一个年级、一种教材、一个主学科验证完整链路；多机构数据隔离必须从 v1 建立，但跨机构经营分析与全量历史迁移不在首发范围。

| 交付物 | 完成定义 |
|---|---|
| 学生端 | 学校作业采集、订正、分层提示、个人图谱、学校预习、可选练习/小测及暂停跳过可用 |
| 坐班老师端 | 现场答疑、能力范围内的证据复核、待核实队列、图谱溯源及报告事实确认可用，不要求补课方案 |
| 教官端 | 观察事实、习惯目标、干预执行、回看验证、交接可用；学科权限隔离 |
| 家长端 | 薄弱点来源、覆盖分母、帮助条件、不确定性、低负担建议及反馈跟进可用 |
| 校区端 | 错题汇总、共性研判、现场支持与沟通待办、待核实和复核容量可用，不派补学课程 |
| 基础服务 | 真实鉴权、持久存储、异步任务、审计、恢复、纠错传播、导出与删除流程通过验收 |
| 内容与运营包 | 有来源的首发内容、教师金标准集、岗位 SOP、培训和异常处理演练记录 |

图谱动画、虚拟形象、积分商城、自由网页浏览、无限开放聊天、自研设备管理、所有学科内容、基础模型训练和模型完全私有部署独立估算，不挤占上述完整流程。

本包中的数据契约和可运行参考内核属于研发参考交付：PostgreSQL DDL 用于正式结构评审；参考服务用内存仓库和固定演示身份，展示隔离读取、老师确认、规则投影/撤销重算、计划、观察干预、预习及半月报告的关键机制。它不接真实 LLM 或学生数据，不等于生产后端、完整终端或上线安全已经完成。所有生产用户故事初始状态统一为 `not_started`（待开发），不得把演示子集的测试通过映射为任一 US 已完成。

## 2 排期成立的前提与责任人

建议工程配置为产品负责人 1、技术负责人兼后端 1、后端 1、前端 2、AI/评测工程师 1、QA 1，另配设计约 0.5、运维/安全约 0.5、平台内容质量人员至少 1 位持续投入（维护课程映射、答案与评测，不承担托管班授课）。坐班老师、习惯支持人员和校区负责人提供试运行时间，不能从研发人数推导运营人力已经解决。学生、家长、坐班老师、教官、校区负责人是五类权限角色，不是每班五个员工岗位；坐班老师和教官可一人兼任。

以下排期以团队熟悉所选技术栈、可使用合适的模型服务、内容首批可供审核、无大规模旧系统迁移、终端采用现有平板与 Web 页面为前提。若需要采购专机、重写原生设备层、全科内容或完全私有模型，应单独添加关键路径。供应商可用性、授权和数据处理安排未确认时，开发用合成样本和适配器桩继续进行，真实数据联调暂停。

角色简称：PO 产品负责人；TL 技术负责人；BE 后端；FE 前端；AI 模型与评测；QA 测试；CUR 平台内容质量；ST 坐班老师；CO 教官；OPS 运维/安全；PM 校区负责人。每项只设一个验收主责，其余为协作方。

## 3 8—12 周的条件化工程计划

建议基线为 12 周：前 8 周完成候选版本与内部全流程演练，后约一个自然月进行两个半月周期的受控运行和修正。只有已有基础设施、内容及团队熟练时，8 周才可能交付可进入试点的候选版本；8 周不包含尚未发生的长期效果验证。半月固定按 Asia/Shanghai 时区的自然月 1—15 日、16 日—月末划分；查询使用左闭右开区间（1 日 00:00 至 16 日 00:00；16 日 00:00 至下月 1 日 00:00）。W9—12 是排期近似，若启动日不在周期边界、跨假期或出勤不足，需要延长至两个完整周期结束。

| 阶段 | 主责与协作 | 工作及依赖 | 阶段退出证据 |
|---|---|---|---|
| W1 需求和契约冻结 | PO；TL/CUR/PM | 冻结首发内容、角色、页面流、状态和错误码；定稿数据契约与指标 | 学生、坐班老师、教官、家长、校区负责人五类角色走查（含一人兼任）；关键流程及至少一份完整学生案例签收 |
| W1—2 工程与内容底座 | TL；BE/OPS/QA/CUR | 真实身份、租户与学生授权、数据库迁移、对象存储、审计、内容版本、金标准集；依赖契约 | 空库部署成功；跨学生/租户负向检查通过；首批题有人工标准 |
| W2—4 采集与确认 | BE；FE/AI/ST/QA | 上传、切题候选、初判、复核、申诉、可靠任务、误判重算；依赖底座 | 真实终端跑通一题闭环及失败恢复；错误不会未经确认进入图谱 |
| W3—5 个人图谱与现场支持 | TL；BE/FE/CUR/CO | 规则投影、前置关系、作业溯源、帮助条件、观察/自述区分、习惯支持、版本修正 | 独立学校作业可验证；未观测点不自动加题；仅教官权限不能改判 |
| W4—6 个人智能体 | AI；BE/FE/CUR/QA | 身份和记忆、上下文包、工具、预算、提示模式、人审、供应商适配 | 两个学生相同提问能引用各自证据；没有跨生读取或直接写掌握度 |
| W5—7 学校任务与轻量选做 | FE；BE/AI/CUR/ST | 学校任务来源、个性化帮助增强、选做三项门禁、默认零预算、预习板块、真实进度 | 学校预习可直接协助；三项任缺不能启动选做；暂停/跳过无欠账 |
| W6—8 半月汇总、报告与校区研判 | BE；FE/AI/ST/PM | 自动汇总已有证据、可选小测条件、锁定快照、报告确认发布、沟通回访 | 无人参加小测也可跨两周期出报告；数字可追溯到来源、分母及帮助条件 |
| W7—8 发布候选与演练 | QA；全员 | 回归、负载、注入、离线、恢复、删除、权限撤回、培训；依赖全流程 | G1 技术门槛全部通过；发布/回滚及运营负责人就绪 |
| W9—10 受控试点周期一 | PM；ST/CO/QA/AI | 10—20 名获适当授权学生；全量学科确认；记工时与学生负担 | 完成学校作业支持—证据汇总—报告—沟通；数据不足、未选做和服务失败分开统计 |
| W11—12 试点周期二与发布评审 | PO；PM/QA/TL/CUR | 针对真实缺陷迭代，保留证据条件和变更记录；执行 G2/G3 | 两个完整周期的证据、可接受的人力负荷、无未关闭发布阻断项 |

粗估工程量可按 50—70 人周评审，包含前后端、AI、QA、集成与发布；不包含驻场运营、全科内容生产或私有模型算力。该范围不应直接乘平均工资当报价：先按实际人员和内容准备度细化任务，再加显式预留。第二周若仍没有可审核内容或数据契约未稳定，应重排后续阶段，不靠省略验收追赶日期。

## 4 工作包与依赖清单

| 包 | 主责 | 前置包 | 可独立验收的产出 |
|---|---|---|---|
| P01 身份与数据底座 | TL | 无 | 授权、租户隔离、迁移、审计、对象访问、备份 |
| P02 课程和内容 | CUR | 内容范围冻结 | 课程关系、题库版本、讲解、评分规则、首批金标准 |
| P03 纠错主流程（首个交付 C0） | BE | P01/P02 | 拍照识别、错步定位、基础提示、坐班转接、订正再检查、申诉与证据 |
| P04 个人图谱与证据 | TL | P01/P03 | 投影、规则版本、反例、撤销重算、变化记录 |
| P05 专属智能体 | AI | P01/P02/P04 | 独立状态、记忆、工具、上下文、模式、人工转接 |
| P06 学校任务支持与可选活动 | FE | P02/P04/P05 | 学校来源、默认零额外预算、三项门禁、暂停跳过、预习关注点及课后关联 |
| P07 现场习惯支持与校区研判 | BE | P01/P03/P04 | 事实观察、错题聚合、答疑与沟通待办、回看和兼任交接 |
| P08 半月汇总与家长报告 | BE | P03/P04/P06/P07 | 已有证据快照、可选小测及不参加路径、来源与分母、报告和沟通 |
| P09 质量与运营保障 | QA | 贯穿 P01—P08 | 自动回归、人工抽检、恢复/删除/隔离演练、培训 |

P05 的适配器和工具桩可与 P04 并行开发，但真实图谱读取和证据失效验收必须在集成后完成。任何把作业证据确认、现场支持或家长反馈当作“系统外人工，因此不必做状态”的实现均不满足完整 v1。工作包及 backlog 的依赖仅表示研发集成顺序，不构成学生执行顺序；US-27/33 对可选小测相关代码的依赖不意味着孩子必须参加小测才能汇总或出报告。

首个交付门槛 **C0** 见 [纠错核心规格](10-纠错核心流程与首发验收.md)。US-03—08、US-16、US-18 在必要基础能力之后优先完成；基础分层提示和现场转接从 P05 前移至 P03，不等待长期记忆。其他 P0 代表完整 V1 必须交付，不代表与纠错平均分配首期优先级。

## 5 用户故事与验收矩阵

本表用于建立需求单与自动/人工测试用例的对应关系。每项必须记录实现提交、测试证据、执行人和日期；状态为 `not_started / in_progress / ready_for_qa / passed / blocked`。下表的状态词是业务行为要求，正式 API 枚举以契约为准，禁止前后端各自翻译出不同状态。

| ID | 用户故事与主责 | 正常路径及状态验收 | 错误与权限验收 |
|---|---|---|---|
| US-01 | 校区管理员创建学生及监护绑定；TL | 正确绑定后监护人可见该生已发布内容；绑定变更留审计 | 非绑定家长读取、枚举或导出学生资料均拒绝；撤销后缓存访问失效 |
| US-02 | 坐班人员进入授权班级；TL | 只查询授权范围；坐班老师和教官可一人兼任，按各自授予权限执行 | 修改 URL、请求体或缓存键不能越权；只有教官权限不得改判；不要求每班配置五个岗位 |
| US-03 | 学生提交学校作业证据；BE | 记录学校任务来源、题目、作答时间和已知帮助条件；重试只产生一次提交，显示 received/processing | 缺图、损坏、超限、伪装格式明确报错；不因图片不清或知识点未覆盖自动加题；文件不可公开访问 |
| US-04 | 坐班老师补正识别与切题；FE | 保存原图、题目边界及人工修订版本；后续分析读取新版 | 题干不完整进入 needs_resubmit 或待核实，不编造条件；不能把无法评分记成答错 |
| US-05 | 学生收到可靠纠错；AI | 区分AI候选提示与已确认判定；有过程时定位第一可确认错步，无过程不编步骤；坐班确认后才写正式图谱与报告 | 正确题及合法等价解法不能误标错；模糊、冲突、无把握转待核实；初判不得伪装已确认 |
| US-06 | 坐班老师采纳或改判证据；BE | 能力及授权范围内确认判定、错误步骤、解释和帮助条件，关联 review_decision | 学生、家长、模型及仅教官权限不能确认；兼任需有老师权限；旧版本提交返回 409 |
| US-07 | 学生申诉误判；BE | 申诉进入待处理，坐班老师新决定替代旧判断；相关证据、图谱、报告和未执行建议可追踪 | 撤销证据不继续影响当前状态及新报告；保留原作答，不因申诉新增罚题 |
| US-08 | 学生完成学校作业订正；FE | 新attempt关联parent_attempt_id及根作答，保存提示；订正后重新检查，明确通过、仍需帮助或待核实 | 只点完成不得通过；原题订正不受额外门禁限制；重复重传去重；提示后改对不算独立掌握，不自动加题 |
| US-09 | 坐班老师溯源知识薄弱点；CUR | 主/关联知识点、错因候选及前置关系分开展示，可回溯学校作业来源、次数和帮助条件 | 无过程或条件不明显示待核实；一次错误不自动定性粗心或能力问题；不生成补课方案 |
| US-10 | 学生查看个人知识图谱；FE | 课程范围叠加个人状态、样本量、日期、证据与不确定性；可查看与当前学校任务的关系 | 未观察节点显示数据不足，不用班均填补，不为点亮图谱派题或以覆盖率惩罚学生 |
| US-11 | 系统用有效作答更新知识状态；TL | 已确认有效证据按版本规则计算；满足可信独立条件的日常学校作业可验证；重放投影一致 | 待审核、撤销、帮助条件不明及答案暴露证据不得冒充独立验证；不得强制小测才计入 |
| US-12 | 老师修正证据或题目映射；TL | 新版本重算受影响状态；旧结果可追溯，依据失效的未执行建议标 stale；历史报告按事实影响范围处理 | 相关重算未完成不能发布新报告；重复事件不累计；截止后无关新增证据不让所有历史报告失效 |
| US-13 | 每个孩子保有专属智能体；AI | 重登/换设备后加载本人图谱、记忆和学校任务上下文；模型升级后个人数据仍在 | 两生同时运行无串用；不得宣称每生训练了基础模型或把参考演示当生产服务 |
| US-14 | 学生获得学校任务优先的支持；AI | 根据本人作业和证据给提示或解释；extra_minutes 默认 0；无新增活动建议是合法成功结果 | 无证据、未完成学校任务、不愿意或无余力均不得自动加题；不虚构表现或超学校进度加课 |
| US-15 | 学生与老师确认长期记忆；BE | 候选→确认→到期/替代；保留来源、确认人和期限；意愿及余力按当前状态更新 | 学生不能确认学科诊断；模型不能把自述写成事实；过往愿意不能替代本次选做同意 |
| US-16 | 学生按需获取分层帮助；AI | 基础纠错先实现位置/方向→必要关键一步→坐班求助，记录帮助；不依赖完整长期记忆；验证求助后如实转有帮助 | 不泄露整页答案或无限反问；未确认提示明确标注，不写成事实；不得拒绝原题求助来保独立分数 |
| US-17 | 智能体受约束地调用工具；AI | 仅访问当前学生批准内容；每次执行重查权限、学校来源、进度及选做门禁，记录理由 | 拒绝未知工具、任意 SQL/URL、跨生 ID、超步数和伪造学校来源；模型或客户端自报不能绕过门禁 |

## 6 状态、错误码与测试夹具

任何用户故事至少覆盖成功、缺数据、无权限、并发修改和外部失败中适用的分支。命令统一返回 `request_id`，异步命令另返回任务编号与可查询状态。HTTP 与业务错误建议固定如下，正式枚举随契约版本冻结。

| 类别 | 建议错误 | 客户端行为 |
|---|---|---|
| 未登录 | 401 AUTH_REQUIRED | 暂停上传/写操作，引导重新认证 |
| 没有角色权限 | 403 FORBIDDEN | 说明该操作需要对应授权，不提供越权按钮；兼任者按已授权限执行 |
| 对象不在可访问范围 | 404 NOT_FOUND | 不暴露其他学生或机构对象是否存在 |
| 并发或过期上下文 | 409 VERSION_CONFLICT / STALE_CONTEXT | 重新读取，展示新旧差异，不自动覆盖老师变更 |
| 业务状态不允许 | 409 INVALID_TRANSITION | 显示当前状态及合法下一步 |
| 输入或证据不满足 | 422 INVALID_INPUT / INSUFFICIENT_EVIDENCE | 指出可修正项或保留数据不足；不能自动生成加题来补证据 |
| 调用配额/负担预算 | 429 RATE_LIMITED / BUDGET_EXCEEDED | 调用限流可排队或转人工；额外预算不足则停止选做，不延期形成欠账 |
| 模型/依赖异常 | 503 DEPENDENCY_UNAVAILABLE | 保持已有任务可用，展示重试或人工处理状态 |

测试夹具至少包含：两机构各两校区、不同授权班级、两名有相似姓名但不同身份的学生、一个跨校区转入学生、一名已撤销绑定家长、教官/坐班老师双角色人员及只有教官权限的人员。证据样本含独立学校作业、正确作答、等价答案、错误过程、部分正确、无过程、看过答案、帮助条件未核实、撤销误判、教材进度变更及重复事件。行为夹具包含额外预算为 0、三项门禁分别缺失、意愿中途撤回、暂停/跳过、学校布置预习、全周期无人小测及图谱有未观测节点。

跨学生和跨租户测试必须覆盖 API、数据库会话、Worker、对象下载、搜索、向量检索、缓存、导出和报告链接。不能只测页面菜单是否隐藏。RLS 需用生产等价非特权数据库账号验证，不能用超级用户测试后认定安全。

## 7 三道发布门槛

C0 是纠错主功能交付关口，G1/G2/G3 是整套产品的试点与发布关口。G1 以 C0 通过为前置；C0 通过也不等于可以跳过其他上线验收。

### G1：可以带真实学生受控试点

硬门槛全部满足才进入受控试点；数值是建议验收目标，启动时可基于范围重定，但不可在失败后悄悄更换分母。

| 门槛 | 建议验收方法与通过条件 |
|---|---|
| 拍照纠错主流程 | C0 场景全部通过；人工兜底不能替代拍照、检查、订正与再检查的完整可用流程 |
| 身份隔离与权限 | 预先列出的全部跨生/租户负向用例零泄漏、零越权写；任一失败即阻断 |
| 证据及状态 | US-06/07/11/12/27/33/39 确定性用例全部通过；独立学校作业可验证；仅帮助条件不明不能冒充独立；重放与撤销重算一致 |
| 不增负门禁 | US-14/19/20/22/25/26 全部分支通过：默认不加题、三项门禁分别缺失均禁止启动选做、暂停/跳过无惩罚无欠账、学校任务可正常求助、不超进度加课 |
| 内容正确性 | 每个上线题型至少 30 个独立金标准样本、总体至少 200 个（研发合成/脱敏测试集，不是给孩子加做的题量）；含典型错误及低质量输入；按切片记录初判与教师确认后结果，不只报总体准确率 |
| 学科发布 | 首发学科事实全量由具备权限且有能力的坐班老师确认；无把握保留待核实；严重错误解释、答案或推荐流出时阻断相关能力，修复后复验 |
| 智能体约束 | 固定注入/跨生/测验套答案测试中零成功越权及泄漏；工具预算、拒绝、截断和超时路径全部通过；不宣称由此证明所有攻击均安全 |
| 引用与报告 | 数字由程序计算并回溯来源及分母；展示帮助条件和不确定性；无新增小测、无新增练习仍能按期汇总发布；无证据捏造阻断 |
| 可靠性 | 断网、重复投递、Worker 崩溃和模型失败演练无已确认作答丢失、无重复业务副作用；待处理记录可查 |
| 数据流程 | 真实数据使用范围、主体授权、供应商安排、留存及退出流程落实；普通开发环境不使用真实学生数据 |
| 运营能力 | 实际承担坐班答疑、习惯支持及管理的人员完成培训（可兼任）；无能力覆盖转待核实；支持积压和投诉有承接人，准备纸笔/人工路径 |

AI 初判效率单独观察：一键采纳率按有效复核题计算，改判原因按识别/判定/知识点/解释等分开。初判不达期望时可以继续受控人工试点，但不能将未确认结果作为确定判错、正式图谱或家长结论发布，也不能宣称自动批改已达标；明确标注的当题辅助提示按 10 文件可用。外部模型基准成绩不替代本项目测试。

### G2：完整 v1 试点验收

至少完成连续两个自然半月服务周期，建议 10—20 名学生。周期开始冻结统计范围、学校进度、知识点覆盖分母和独立证据规则，自动汇总已有证据，不为验收要求孩子完成规定题量。小测完全可选；无新增练习/小测仍是有效试点样本。缺席、未采集、未选做、条件不明和转人工分列，不因数据少或没有改善而静默删除学生。

| 验收维度 | 计算口径和通过判断 |
|---|---|
| 功能完整 | US-01—40 中适用于首发范围的项目全部有证据；明确不适用须 PO 与 QA 联合说明，不能据此豁免核心模块 |
| 服务完成 | 报告按时率=按时发布份数/应发布份数，建议≥90%；答疑/待核实和家长反馈按承诺处理时限另报。选做完成率、小测参与率和图谱填满率不作服务通过门槛 |
| 学习证据 | 每生展示范围内知识点总数、已观察数、有效独立证据覆盖数及其分母；列学校作业来源、出现次数、帮助条件与反证。只采错题不得计算全量错误率；无改善或数据少如实说明，不承诺提分 |
| 个性化 | 至少 5 组同课不同薄弱点案例，坐班老师确认提示方式、溯源解释或预习关注点差异有依据；允许双方额外题量都为 0；跨周期体现新证据与记忆修正 |
| 人力容量 | 实测作业证据复核、现场答疑、习惯记录和沟通时间不超过实际排班；兼任工时不重复计算；无把握转待核实，不以承担补课或隐性加班算通过 |
| 学生负担 | 新学生额外预算为 0；选做均有完成学校任务、意愿、余力和预算记录；抽查暂停/跳过后无扣分、欠账或自动补做；学校任务优先且不因图谱缺口加题 |
| 家长可理解性 | 抽样回访能说清薄弱点来自哪些作业、覆盖多少范围、是否得到帮助、哪些尚不确定及低负担建议；反馈有回执；只打开报告不等于理解 |

90% 仅是报告按时率的试点建议目标，不是孩子做题、小测或图谱覆盖要求；不适用于鉴权、证据造假或严重内容错误等硬门槛。必须同时展示人数和分母；例如 9/10 与 90/100 不能当成同等确定的长期结果。

### G3：可扩大日常运营

必须满足 G1/G2，关闭所有阻断项，并具备生产发布、回滚、备份恢复和应急值班记录。关键的模型/题型覆盖和老师容量须随扩大范围重新验收；不能把一个班数学通过视为多校区全学科通过。

性能基线建议在声明场景下测试：例如 100 名同时在线、20 份作业在 5 分钟内提交。普通列表读取建议 p95≤1 秒，上传确认 p95≤2 秒，模型处理进度必须可见；AI 完成耗时另报 p50/p95，不能包含老师等候时间后仍称纯模型延迟。数字是起始 SLO，不是当前性能。上传确认只代表元数据和完整性确认，不承诺两秒传完大图。

建议恢复目标 RPO≤24 小时、RTO≤4 小时作为首发讨论起点，生产负责人须按业务容忍度签收并演练。持久数据库恢复窗口内仍可能损失未备份数据；若业务要求更低 RPO，需配置相应增量日志和恢复机制，不能以 Worker 幂等代替备份。

## 8 缺陷、回滚与范围变更

P0：跨学生泄漏、未授权写、严重不当内容外发、不可恢复的数据损失。立即停止受影响功能，保留最小必要证据，人工承接并启动修复。P1：误判未撤回、图谱状态错误、可选测验泄题、报告数字错误、默认加题/绕过选做门禁、跳过产生欠账、超学校进度加课、无小测就不能出报告、核心流程无法继续。不得带入扩大运营。P2：有可靠人工替代的局部问题，可记录负责人和期限后继续受控试点；不能重复展期而无修复。

模型切换先冻结新调用或退回上一已验证路由，业务数据不随模型回滚而删除。数据库采用向前兼容迁移；已执行迁移的回退需专门方案，不能仅回滚应用镜像。内容版本和规则版本独立发布，历史结果保留原版本标识。

任何扩科、增加年级、增加数据来源、开放新工具或改变独立验证规则，都提交变更单：目的、影响用户、内容/权限/数据影响、研发量、评测样本和回滚条件。由 PO 负责范围，CUR 负责教学正确性，TL/OPS 负责系统及数据，PM 负责实际人力。

## 9 发布交接包

最终交接必须包括：发布版本和覆盖清单；数据契约与迁移；配置及密钥交接说明；内容来源和版本；锁定评测集与结果；US-01—40 验收记录；岗位操作手册；权限名册；备份恢复和删除演练；已知限制；异常联系人；模型与内容变更流程；试点报告及下一阶段范围。

评测持续进入发布流程。模型、提示词、图谱、评分规则、工具权限或检索策略变更，均按影响范围触发回归；真实改判与事故在去除不必要个人信息后回流测试集。任务特定评测和持续回归可参考 [OpenAI Evaluation best practices](https://developers.openai.com/api/docs/guides/evaluation-best-practices)，具体作业支持与证据标准由平台内容质量人员负责，而非由通用模型评分替代。
