# 02｜个人知识图谱与成长证据

版本：v3.1，2026-10-16。定位：托管班的日常学校作业支持、个人知识图谱与家长汇报设计稿。本文的状态门槛、题量和时间参数是试点规则，不是研究已证明的学习规律。外部依据见文中链接与配套《03-学习科学与效果验证》。

## 1. 产品核心：从日常学校任务形成可解释的个人学习状态

服务边界是托管：平板 AI 支持孩子自主完成学校课程与作业，减少对成人提醒和代解的依赖；坐班老师处理现场作业答疑，不另行补课或安排机构课程。教官负责现场习惯支持，可由同一位有相应能力的人员兼任，不要求配齐五个独立岗位。

每个孩子拥有自己的知识图谱、成长记录和长期专属 AI 智能体。这里的“独有”体现在学过什么、在哪种题目中遇到困难、得到过什么帮助、后来能否独立完成，以及下一步应该做什么。相同课程知识可以共用，个人证据和学习路径必须隔离。

建议采用四层结构：

| 层 | 保存内容 | 维护责任 |
|---|---|---|
| 共享课程图谱 | 学科、教材、章节、知识点、技能、前置关系、题目映射 | 教研审核发布，AI 辅助整理 |
| 个人知识状态 | 每个知识点的当前状态、证据充足度、复习安排、未解决问题 | 规则引擎根据有效证据计算，老师可更正 |
| 个人证据与成长时间线 | 学校原始作答、订正、后续学校新作业证据、可选小测、现场答疑、习惯观察 | 各责任角色写入，保留来源和版本 |
| 专属智能体记忆与计划 | 当前目标、已验证的辅导偏好、任务、未完成承诺、可引用的历史 | 智能体读取授权数据生成建议，受业务规则约束 |

学生无需理解图数据库，首页回答三个问题：学校今天布置了什么、卡住时怎样获得适量帮助、哪些任务已经完成。系统从日常过程积累证据，不让孩子为填满图谱另做一套任务。个人地图应能点开证据，不能只展示一张不断变绿的装饰图。

知识追踪研究提供了从作答序列估计状态的思路，但模型预测不等于直接测量孩子的全部知识。BKT 原始工作是在程序学习中追踪规则掌握；本项目需要自行验证向中文教材、手写数学作答和线下托管场景迁移后的有效性。[Corbett 与 Anderson 原论文](https://link.springer.com/article/10.1007/BF01099821)

## 2. 共享课程图谱：把日常学校作业映射到明确范围

首期围绕学校实际教材和进度建设图谱。纠错、知识点分析和半月家长汇报构成日常闭环；举一反三、额外复习、机构建议的预习与轻量小测保留入口，但只能按必要性、自愿和余力使用。学校布置的预习属于原任务。无需让每个孩子每个周期都完成六类活动。

### 2.1 节点字段

| 字段 | 说明与示例 |
|---|---|
| `knowledge_id` | 永久标识；改名不换 ID，拆分时创建新 ID 并保留迁移关系 |
| `node_type` | subject / chapter / concept / skill；章节只作组织，不直接视为单一能力 |
| `name`、`definition` | 例如“分配律：外部因数乘括号内每一项”；定义写清适用范围 |
| `curriculum_refs` | 学段、年级、教材版本、册次、章节、课次，多教材可映射同一核心概念 |
| `observable_objective` | 能在包含正负数的代数式中正确展开括号，并解释每项的变化 |
| `coverage_facets` | 需区分的子范围，如正因数、负因数、分数系数；有证据才判断，不为覆盖率增加测验 |
| `misconception_codes` | 漏乘、负号处理错误等常见错误模式；不是给学生贴永久标签 |
| `graph_version`、`status` | 草稿、审核中、已发布、已停用；记录审核人和生效时间 |

颗粒度原则：能解释具体作业步骤并支持一次明确答疑。过粗的“代数能力”无法指导任务；过细到每道题一个节点，又无法积累跨题证据。教研先以真实作答样本校准，再发布首版节点词典。

### 2.2 边与题目映射

关系字段至少包括 `edge_id`、`from_id`、`to_id`、`relation_type`、`scope`、`rationale`、`source_ref`、`reviewer_id`、`graph_version`。采用四类主要关系：

- `part_of`：知识点属于哪个章节，用于浏览和报告汇总。
- `prerequisite_of`：理解后续任务通常需要的前置点，必须说明适用题型。
- `related_to`：有关联但不声称教学先后。
- `equivalent_to`：教材表述不同但教学目标等价，须经审核。

例如“分配律 → 去括号解方程”，“最小公倍数 → 去分母解方程”。前置边用于提出诊断问题，不能因一道去分母题错误，就把全部上游节点批量标红。边可有例外，不能作为禁止学生接触下一课的硬门槛。

每题保存 `item_id`、`item_version`、`item_family_id`、来源与授权、题干、标准解与评分细则、难度档、主知识点、辅助知识点、步骤映射、覆盖子范围、审核状态。图谱负责“这题涉及什么”；`evidence` 负责“这次作答实际证明了什么”。一道多知识点题答错，只有被定位并确认的步骤才能给对应节点提供负面证据。

## 3. 每个孩子的状态：掌握、证据和复习分开

个人业务对象统一携带 `tenant_id`（机构）、`campus_id`、`student_id`。共享图谱不保存学生数据；机构自建内容另外标注机构归属和授权范围。

`student_knowledge_state` 的主键为学生与知识点组合，至少包含：

| 字段组 | 字段 |
|---|---|
| 当前判断 | `learning_status`、`diagnostic_record_ids`、`reason_codes`、`coverage_facets_verified` |
| 证据条件 | `evidence_sufficiency`、`valid_evidence_count`、`independent_dates_count`、`distinct_item_families_count` |
| 时间与验证 | `last_error_at`、`last_independent_success_at`、`delayed_verified_at`；`review_due_at` 仅可作为工作人员回看提示，不生成学生加练义务 |
| 可追溯性 | `evidence_ids`、`graph_version`、`rule_version`、`state_version`、`computed_at` |
| 待处理事项 | `open_questions`、`disputed`、`stale`、`teacher_override_ref` |

`learning_status` 可记录“尚无判断、当前作业需帮助、正在巩固、阶段性较稳”；它与诊断类别分开。新增 `diagnostic_status`：`observed_error` 是原作答中已确认的错误事实；`suspected_cause` 是待核实原因；`verified_weak_scope` 是有足够相关作答与坐班答疑支持、经人工确认的具体薄弱子范围；`unknown` 是资料不足或有矛盾。四者可通过独立诊断记录并存，不能将猜测覆盖成事实。

例如“10 月 8 日第 6 题第二行漏乘”是错误事实；“可能没有理解分配律”是原因假设；“近两周可判断的 5 道负数去括号题中，3 道出现同类错误，坐班答疑时确认未理解负号处理”才能支持限定范围的薄弱判断。只有答错次数而没有分母、帮助条件和解释，不能下结论。

“是否学过”单独记录。学生未学不等于薄弱；长期没有新数据不等于退步；待观察不等于欠测。系统不以图谱未达某档要求补作业。

证据充足度显示“资料不足、有限证据、证据较充分”，并附解释，例如“只有 1 次作业记录，独立完成情况未知”“来自 3 个日期、2 类题目的独立作答”。不直接显示“掌握度 87.3%”。内部若引入概率模型，也必须标注它预测的对象、适用题型和校准情况，不能把概率当成智力分数。

要区分三种不确定性：图像是否读对、答案是否判对、知识状态是否足够明确。老师确认答案只解决第二项，不会自动消除样本不足。模型自己说“我很有把握”不构成任何一项的量化证据。

## 4. 证据事件：长期记忆的可靠来源

一次 `attempt` 是一次实际作答；一条 `review_decision` 是一次核验或改判；一条 `evidence` 是从作答中提取的、对某个知识点有效的观察。不得把三者混成一段 AI 摘要。

每条 `evidence` 保存：身份键、`evidence_id`、`attempt_id`、`review_decision_id`、知识点和步骤、`event_type`、`occurred_at`、`recorded_at`、`result`、`assistance_level`、`assessment_id`、`intervention_id`、`item_family_id`、原始材料引用、来源角色、有效性、`supersedes_id`。结果支持 correct / incorrect / partial / unscorable，帮助程度支持独立、方向提示、关键步骤提示、看过完整解析、未知。

事件类型包括学校作业首次作答、订正、后续学校新题、可选变式、可选小测、口头解释、现场作业答疑、习惯观察。老师答疑过是服务记录，不能当成答对；学生说“懂了”是自述，不能当成独立证据。

**学校日常新作业可以直接作为有效独立证据**：记录学校作业日期、页码题号与步骤；核实本次未使用 AI/成人/同伴提示或答案；核实不是刚订正过的原题或已看过答案的重复题。题型相同不妨碍成为新题，但同模板密集出现需控制相关性。自述不能单独证明独立；结合现场观察及工具使用记录，由有权人员确认。无法核实即记帮助条件未知，不加测来凑证据。学校新题自然间隔出现，也可提供延迟证据。

写入流程：采集材料 → 识别与诊断草稿 → 核验结果 → 提取有效证据 → 重算个人状态 → 支持当前学校任务（额外建议须通过选做门禁） → 更新智能体可用记忆 → 生成报告草稿。通过 `outbox_event` 分发变更，事件消费必须幂等。同一照片重传、同一订正重复提交不能累计为多次掌握证据。

`agent_run` 保存此次建议读取的状态版本、证据清单、调用工具、生成结果与审核情况。这样才回答得了“智能体为什么针对当前学校作业采用这种提示，以及它引用了哪些历史证据”。

## 5. 可解释规则基线与后续模型

首版先用版本化规则运行，保留算法替换接口。下表为 R1.1 示意规则，用于解释已有证据，不是要求孩子达标的训练处方。阈值不满足时可以持续保持未知；不得为了达到阈值强制增加作答。

| 条件 | 状态处理 |
|---|---|
| 未复核、无法识别、存在判题争议 | 不作为有效对错证据；保留待处理任务 |
| 只有一次错误 | 标出待诊断问题；不直接宣布完整知识点薄弱 |
| 多个相关学校作业出现同类错误，且帮助条件与分母清楚、现场答疑确认具体缺口 | 可记录 `verified_weak_scope`，限定到具体子范围；给出支持当前学校任务的最小建议 |
| 经现场答疑或提示后订正正确，但尚无独立新题 | “正在巩固”，等待后续学校新作业提供证据；无新增测试义务 |
| 最近一次有效错误之后，至少两个不同日期出现独立新题正确，最早与最晚有效正确作答的实际间隔至少 24 小时，且覆盖当前声明的子范围 | 可进入“阶段性较稳”；跨日期不自动等于延迟保持已验证；24 小时为演示可调参数 |
| 再次出现已确认错误 | 进入针对该子范围的复查；保留历史进步，不清空全部节点 |
| 没有新增独立作答，或未参加可选小测 | 保留已有判断及其时效限制，缺少的部分标未知；不扣分、不生成欠测或补测任务 |

同模板集中练习可能高度相关，按证据簇控制贡献；高层节点不得直接取子节点平均分。展示“本章 8 个目标中，5 个有独立验证、2 个仍需巩固、1 个资料不足”，比一个含糊总分更有意义。

延迟证据优先从后续学校新作业自然取得，不单独强制调度复测。演示规则将本轮首次有效独立正确作答设为起点，“本轮”指最近一次有效错误之后；没有错误历史时从首次有效独立正确作答起算。在满足阶段性较稳条件后，若另一次有效独立新题正确发生在起点至少 7 个实际日之后，才置 `delayed_verified=true`。生产环境若记录了明确的现场答疑完成时间，可以另行配置以该时间为起点，须保存起点类型、时间与规则版本，不得混用。24 小时与 7 天均为演示可调整参数，不是学习科学结论。若刚刚重新看过答案，要重新记录帮助和时间条件。观察规则可以变，历史事实不能随规则修改被改写。任何额外活动都必须经过学校任务已完成、有余力、孩子愿意三项门槛；没有额外活动不妨碍出半月报告。

后续先让 BKT 或简洁统计模型在影子模式预测，再与 DKT 等模型比较。DKT 的研究任务主要是预测未来作答表现；预测优势不能直接解释为教学增益。[DKT 原论文](https://papers.neurips.cc/paper_files/paper/2015/file/bac9162b47c56fc8a4d2a519803d51b3-Paper.pdf) 一项对照研究发现扩展 BKT 在所考察数据上可与 DKT 表现相当，因此没有必要把深度模型作为首版图谱成立的前提。[Khajah 等](https://arxiv.org/abs/1604.02416)

升级条件是按时间隔离、按学生隔离的验证表现更稳，概率校准可靠，且真实任务选择没有恶化。题目多知识点展开时，同一次答案不能泄漏到自身预测输入；pyKT 已指出此类评估错误会抬高结果。[pyKT 原论文](https://papers.neurips.cc/paper_files/paper/2022/hash/75ca2b23d9794f02a92449af65a57556-Abstract-Datasets_and_Benchmarks.html)

## 6. 冷启动、矛盾与更正

入班先收最小必要信息：年级、教材、学校当前进度、近期样本、学生目标与可用学习时间。家长说“计算粗心”保存为待验证的家长描述，不直接变成节点状态。

入班导入近期学校作答建立局部图谱，随着自然发生的学校作业和现场答疑逐步补足。必要时围绕当前题追问思路，不默认另发入班测验。允许大面积“资料不足”，不要求首次测评覆盖全学科，更不从年级平均水平填出完整图谱。

矛盾按来源追查：作业全对、独立小测错误，优先检查帮助条件和题目差异；简单展开会做、负数系数不会，拆开覆盖子范围；连续错误后突然全对，先核对是否重复题或看过解析。系统提出需复核的差异，不能自行断言代做、作弊或态度问题。

更正使用追加记录。老师撤销错判时新增 `review_decision`，原 `evidence` 标失效并记录替代关系，状态从有效事件重算。依赖旧状态的 `learning_task`、`memory_item` 和未发送 `report` 标 `stale`，重新生成或确认；已发送报告保留旧版本并给出明确更正。图谱节点拆并也要留迁移表，不把旧证据盲目复制到多个新节点。

## 7. 六核心功能怎样围绕图谱运行

| 功能 | 读图谱做什么 | 写回什么 |
|---|---|---|
| 纠错 | 找到本题相关节点、历史同类问题与可用提示 | 经过核验的错误步骤、订正、尚未验证点 |
| 知识点分析 | 结合原作答、同类历史与现场答疑核实当前卡点 | 错误事实、原因假设、已核实薄弱范围、未知项分别保留 |
| 举一反三 | 学校任务完成、有余力且孩子愿意时，必要才选少量变式 | 独立性与覆盖情况；拒绝或跳过不产生欠账 |
| 下一课预习 | 学校布置的直接作为原任务；机构建议的需满足三项自愿门槛 | 已查看内容、待课堂解决的问题；不因未参与判薄弱 |
| 错题整理与可选小测 | 自动归档学校错题，轻量小测仅自愿且确有必要时使用 | 原作业与订正历史；可选测验独立条件；未参加无欠补测 |
| 家长汇报 | 每半月汇总学校作业证据、帮助条件、现场答疑及最小下一步 | 固定半月报告；证据不足照实说明，不等小测完成 |

`learning_task` 必须区分 `task_origin=school` 与 `task_origin=optional`，带学校任务来源、目标、来源证据、帮助记录和停止条件。学校截止时间按真实布置记录；额外活动没有强制截止时间和补做债务，须记录学校任务完成、有余力、孩子自愿三项条件，允许随时结束。优先减少不必要提醒，不把合理求助视为不自主。

半月周期统一为自然月 1 日至 15 日、16 日至月末，按 `Asia/Shanghai` 确定数据截止。数据窗口采用左闭右开：上半月为 1 日 00:00 至 16 日 00:00，下半月为 16 日 00:00 至次月 1 日 00:00。报告每期必须生成，即使只有出勤、学校任务完成情况和“暂无足够学科证据”。可选小测日期按实际到班和孩子意愿安排，未参加不影响报告，不标缺测风险、不欠补测。首次加入的孩子标注“不足完整周期”与实际观察天数，不与完整周期直接比较。家长的具体薄弱点卡应显示原学校作业日期、页码题号和错误步骤、帮助条件、同类频次与分母、可信程度、坐班答疑内容、仍不知道什么、支持学校任务的最小下一步。学校作业题量和难度不同，不能直接横向排名。

## 8. 长期成长记录与线下习惯支持

成长时间线的一条完整记录是“起点问题—采取行动—验证结果—仍有限制—下一步”。例如：“10 月 1 日学校作业展开括号漏乘；坐班老师围绕该题答疑；10 月 2 日、3 日学校新作业独立完成；10 月 9 日学校另一题独立完成；分数系数尚无证据。”时间线允许停滞和反复，不能只保留好消息。

教官记录具体行为：何时开始任务、是否先尝试再求助、是否主动复查、用了几次提醒。每条 `intervention` 写观察、约定、实施与回访，不写“懒”“低自控力”等人格结论。任务耗时、离开设备或未完成不能直接推出注意力障碍、心理状态或学习潜力；设备离线、身体不适和作业量变化需要作为背景。

习惯变化与知识变化并列展示，不做简单因果归因。教官可以说“这周 4 次按约定先检查符号再提交”，不能仅据此说“专注力提高了 30%”。当前学校作业的疑难由坐班老师答疑，教官负责执行支持、观察和转介。一个人可兼任两种职责，但应分别记录学科判断和行为事实，不安排机构补课。

专属智能体的 `memory_item` 应有类别、原始出处、确认人、有效期和修订历史。稳定事实、近期目标、未确认推测分开存储；召回时优先取当前知识状态和证据，再取必要摘要。学生过去的困难应附时间范围，避免一年后仍用旧标签影响任务。长期陪伴通过连续记录和履行计划实现，无需为每个孩子训练一套独立大模型。

## 9. 实现与阶段验收

首版可用关系型数据库保存节点、边、证据和个人状态；图形界面只读取所需子图。是否引入专门图数据库取决于查询需求与规模，不决定产品是否拥有个人图谱。

`prototype/core.py` 是简化参考内核，采用布尔判题、少量节点与题目，不含真实模型调用和持久化存储。v3.1 以本文为目标：日常学校新作业在条件核实后可提供独立证据；额外活动自愿；半月报告不依赖小测。若内核沿用仅练习/考试才算独立、自动添加训练任务等旧口径，应按本规范调整后再用于托管产品演示。

上线前用预设场景验收：未确认结果不改变状态；同一上传不重复计数；有提示订正不冒充独立掌握；多知识点题不整体扣分；老师撤销能重算并使旧计划失效；跨机构读取被拒绝；换教材能保留可迁移的证据与不确定项。

第一个周期验收学校作业支持、证据追溯和错误/假设/薄弱范围/未知的区分；第二个周期验收无需小测也能出准确半月报告、更正能回流、孩子可以拒绝额外活动。跨周期以学校作业完成质量、自主性与提醒依赖、孩子负担、证据可靠性为主指标。自然出现的延迟证据可补充说明；没有出现时报告不足，不能靠追加测验完成验收。
