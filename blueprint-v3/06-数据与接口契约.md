# 数据与接口契约

版本：v3.3，一期独立纠错记录与后续学习证据分层。正文定义生产目标；`contracts/schema.sql` 是基础结构，`openapi.reference.json` 是参考内核已实现的接口子集。完整生产响应模型、认证适配和迁移须按首轮研发评审冻结，不能用演示接口替代全部接口验收。

一期生产契约以 [PHASE1](../PHASE1.md) 的数据要求为起点：照片、识别、作答、判定、帮助、订正和改判必须独立持久化，不以知识点已映射、图谱已建立或长期智能体已创建为前置。下文 `evidence.v1` 是知识目标证据，不能用其必填目标字段阻断一期原始纠错记录。正式迁移与完整请求/响应由一期 P1-01/P1-12 冻结、实现和验证，当前参考 OpenAPI 不代表 App 接口已齐备。

## 1 统一身份与术语

`tenant_id` 表示托管运营方的数据租户，`campus_id` 表示托管点（沿用“校区”技术字段），`student_id` 表示孩子。该数据命名不定义业务为教育培训机构。`teacher` 表示坐班答疑与证据核实权限，`coach` 表示习惯与现场支持权限，可以由同一工作人员按授权兼任。共享课程知识结构按版本发布，学生状态与证据按运营方、校区和学生隔离。运营方自建题目与通用内容的可用范围单独管理。

外部接口统一使用 student；“learner”只用于文字中的学习者或示例文件名，不另造第二套业务 ID。岗位授权由服务端从已验证身份和当前关系推导，不相信浏览器提交的角色、机构或监护关系。

| 对象 | 单位 | 关键关系 |
|---|---|---|
| `attempt` | 一次实际作答 | 原题、学生、帮助条件、时间、学校原任务或可选核实 |
| `review_decision` | 一次确认、改判或撤销 | 对应作答、审核人、前序决定与原因 |
| `evidence` | 对一个具体目标有意义的观察 | 作答/复核或行为来源、目标、有效性与替代关系 |
| `student_knowledge_state` | 一个学生的一个知识目标状态 | 有效证据、规则和图谱版本、覆盖范围 |
| `student_agent` | 学生长期智能体身份 | 独立记忆、目标和运行记录 |
| `agent_run` | 一次受约束的推理与工具执行 | 上下文快照、策略、证据修订号、用量 |
| `memory_item` | 一条可治理记忆 | 来源、确认、有效期、替代和删除状态 |
| `learning_task` | 学校原任务或少量选做支持 | 来源、学校要求、时长、意愿、余力、责任人、暂停/跳过与证据 |
| `intervention` | 一次学科或习惯支持安排 | 发现、约定、执行、回访和结果 |
| `assessment` | 一次孩子自愿参加的轻量核实 | 内容版本、参与意愿、余力、作答条件、跳过；不作为报告前置 |
| `report` | 一份锁定事实的说明 | 周期、证据快照、确认、发布和更正 |
| `communication` | 一次需处理的家校沟通 | 参与人、问题、约定、任务和回看时间 |

成长不是一张可任意加分的余额表。`growth_milestone` 是基于有效证据形成的视图或领域记录，区分独立完成、延迟保持、迁移和行为改善，保留核验条件与反证。生产可按查询负载建立物化视图，不能让模型直接增加成长分。

## 2 时间、版本与样本口径

所有时间存 UTC `timestamptz`，展示和服务周期使用 `Asia/Shanghai`。保留 `occurred_at`（实际发生）与 `recorded_at`（写入）以支持离线补传，迟到事件按实际发生时间参与相应分析，同时触发相关快照复核。

自然半月采用 `[月初 00:00, 16 日 00:00)` 与 `[16 日 00:00, 次月 1 日 00:00)`，按上海时间生成后转 UTC。补测记录实际作答时间与原定周期，不能回填为当时已经完成。中途入班或资料不全显示实际覆盖天数。

同一张图片重传与同一业务请求重试需要幂等；学生再次实际作答应产生新的 attempt。同一道题再次答对不能自动作为“未见过的新题”。同题族集中练习按证据簇控制贡献，具体聚合规则版本化。

`evidence_revision` 是学生有效事实流的修订号，`projection_revision` 是当前投影已处理到的位置。另保存图谱、题目、评分细则、策略、提示词、模型路由与评测集版本。状态接口显式返回 `projection_pending`，消费者不得把“消息已提交”解释为“所有统计已更新”。

## 3 证据契约

生产 `evidence.v1` 至少包含身份范围、来源类型、目标知识点、实际/记录时间、`effective_from`（影响的最早学习时间）、结果、帮助情况、独立条件核实、题族、复核引用、替代引用和有效性。改判在今天发生，但影响起点应指向原作答发生时间；这决定哪些历史报告需要更正。

结果使用 `correct / incorrect / partial / unscorable`；帮助使用 `none / direction_hint / step_hint / answer_seen / unknown`。`none` 只是记录的帮助量，独立作答条件还需要核实。真实学校新作业可提供独立证据，无须另设测验；订正、重复原题或提示后完成不能冒充独立新题。模型初判不作为有效掌握证据，无法判分和未参加可选核实不写成错误，不产生补测欠账。

所有引用必须同运营方、同校区、同学生，且来源类型匹配。JSON Schema 负责结构；数据库约束和领域服务负责引用存在、授权、时间顺序、状态及题目版本。数组中的证据 ID 不能只做字符串校验。

## 4 生产接口目录

所有路径以 `/v1` 开头。GET 不产生学科或服务状态变化；写命令返回资源 ID、版本、`request_id`，异步任务另返回 `job_id` 与查询链接。

| 能力 | 主要接口 | 主体和关键检查 |
|---|---|---|
| 建档与监护关系 | `POST /students`、`POST /students/{id}/guardian-links` | 管理权限、关系核验、同意与审计 |
| 学校进度 | `PUT /students/{id}/course-progress` | 教师确认、教材与课节版本、乐观锁 |
| 上传 | `POST /uploads`、`POST /uploads/{id}/complete` | 文件类型/尺寸、签名短链、关联学生 |
| 作答 | `POST /students/{id}/attempts` | 幂等、内容版本、帮助条件、原始材料 |
| 识别与诊断 | `POST /attempts/{id}/analysis-jobs`、`GET /jobs/{id}` | 当前题型支持、状态与失败原因 |
| 复核与申诉 | `POST /attempts/{id}/review-decisions`、`POST /attempts/{id}/appeals` | 学科授权；旧版本冲突；替代链 |
| 图谱 | `GET /students/{id}/knowledge-graph`、`GET /students/{id}/knowledge-states/{kp}` | 子图深度、证据、快照及未知项 |
| 课程与内容 | `POST /curricula/{id}/versions`、`POST /content/{id}/approve` | 平台内容质量权限、题目授权、不可变发布版本 |
| 智能体 | `POST /students/{id}/agent-runs`、`GET /agent-runs/{id}` | 当前学生范围、模式、预算、工具名单 |
| 记忆 | `GET /students/{id}/memories`、`POST /memories/{id}/decisions` | 分类、出处、确认权限、到期与更正 |
| 任务与选做计划 | `POST /students/{id}/plans`、`POST /plans/{id}/approve` | 学校来源、选做门禁、预算默认零、内容已审核 |
| 任务执行 | `POST /tasks/{id}/commands` | 显式动作与合法状态转换、离线幂等 |
| 预习 | `POST /students/{id}/preview-proposals` | 已确认下一课，前置点与个人证据 |
| 教官观察 | `POST /students/{id}/observations` | 事实/自述/推测分离，机会与提示条件 |
| 支持与交接 | `POST /interventions`、`POST /handoffs` | 分工、负责人、执行与回访 |
| 半月测验 | `POST /assessments`、`POST /assessments/{id}/lock` | 按需可选、无欠账、题目保密、条件锁定 |
| 测验参加 | `POST /assessments/{id}/participations` | 参加/跳过、无惩罚、支持条件与实际时间 |
| 报告 | `POST /students/{id}/reports`、`POST /reports/{id}/confirm`、`POST /reports/{id}/publish` | 作业证据/习惯核实、投影追平、数值一致；无测验也可发布 |
| 沟通 | `POST /communications`、`POST /communications/{id}/followups` | 对象授权、负责人、约定和回执 |
| 校区分析 | `GET /campuses/{id}/insights` | 聚合分母、采集覆盖、权限与小样本 |
| 数据权利 | `POST /privacy-requests`、`GET /privacy-requests/{id}` | 身份核验、导出或删除范围、传播回执 |

这张表定义完整产品边界，不声称上述路径均已实现。参考内核路径中 `/reviews`、简化 `/plans` 等与目标目录有差异，生产集成应冻结一次正式契约后再生成客户端，不能直接把演示 OpenAPI 当作全量服务规范。

## 5 三个核心命令

**订正关联与再检查（v3.2 新增目标）**：正式 attempt 需补齐 `parent_attempt_id`、根作答追溯与对应核验版本，使每次订正关联到被订正的原作答；关系必须同租户、校区、学生与同题版本，拒绝循环、自引用及无源订正。再检查产生新的核验决定，只有通过才显示原题订正成功；暂停或未解决不标成功。当前 SQL/参考 API 尚未实现这些字段与闭环，须作为 C0 优先补齐，见 [10 纠错核心规格](10-纠错核心流程与首发验收.md)。

**复核命令**包含 `attempt_id`、`expected_version`、`idempotency_key`、对错或不可判结论、步骤判定、知识点映射、独立条件确认、原因、`supersedes_review_id`。服务器验证操作者的学科权限，追加决定并更新证据修订号；同一事务写 Outbox。

**学校任务与选做边界**：`task_origin=school|optional` 必须由已核实的学校任务来源或坐班记录确定，不接受模型把选做改标学校要求。额外预算 `extra_minutes` 默认 0；开始选做前服务端核实 `school_tasks_complete && child_willing && has_capacity`，保留核实人、时间和上下文版本，并按整个计划限制总量。可选 `assessment` 与其他选做共享预算，不能另开额度；数据库保存默认 0 的预算和预计时长，激活时校验，服务端事务控制所有活动合计。学校已布置的预习属于 school，不受“其他任务全完成”门禁。`paused/skipped/cancelled` 是正常状态；选做不得有强制截止、扣分或跨日欠账。

**计划建议**包含 `context_snapshot_id`、目标、候选内容、证据引用、预计时间、停止条件和不确定项。模型只能创建建议；老师采用时再次检查版本、预算与内容有效性。已开始任务需要显式调整，不能因新一次模型运行直接被覆盖。

**家长关注点**至少包含 `knowledge_id`、错误事实、来源作业与日期/步骤、帮助条件、已核实作答与错误次数、独立证据次数、范围限制、待核实错因、已知变化、坐班答疑与适量建议。未知项与薄弱项分开，次数分母仅代表已观察样本；缺少全量学校任务不能计算学校作业完成率。正式生产将这些字段冻结为响应 Schema；参考内核使用 `focus_items` 和 `unknown_knowledge_ids` 展示部分机制。

**报告发布**包含 `report_id`、`expected_version` 和幂等键；接收对象从已确认监护关系解析。发布前检查学科与习惯段确认、证据修订号、投影修订号、数字一致性和报告是否过期。报告不要求有测验记录或足够证据；证据不足也要准确显示未知，不自动生成追加题。消息结果未知时进入待核实，不重复盲发。

## 6 幂等、并发与错误

学员命令的幂等范围为运营方、校区、学生、操作者、命令类型和幂等键；持久保存规范化载荷摘要与处理结果。同范围同键同载荷重试不重复执行；同范围同键不同载荷返回冲突。跨学生批量操作拆成各学生的子命令并各自生成键。计划和报告的回放应返回资源引用及当前有效性，不能把原缓存中的“未失效”误当成当前状态。

对象写入携带 `expected_version`，证据驱动操作另外检查 `evidence_revision`。多个老师并行确认时只能有一个后继决定生效，其余读取最新状态后重试。学科事实写入、修订号、Outbox 与去重记录必须原子提交。

| HTTP | 生产错误码 | 处理方式 |
|---|---|---|
| 400/422 | `VALIDATION_ERROR` | 返回字段与可修正原因 |
| 401 | `UNAUTHENTICATED` | 重新建立身份，不显示敏感资源 |
| 403 | `FORBIDDEN_ACTION` | 范围内但动作无权限 |
| 404 | `NOT_FOUND` | 不存在或不在可见范围，避免枚举泄漏 |
| 409 | `VERSION_CONFLICT`、`IDEMPOTENCY_CONFLICT` | 读取最新状态或使用正确的新命令 |
| 409 | `STALE_EVIDENCE`、`INVALID_TRANSITION` | 重算或重新确认；不绕过 |
| 429 | `BUDGET_EXCEEDED` | 保留任务，限流或转人工 |
| 503 | `DEPENDENCY_UNAVAILABLE` | 查询异步状态、重试或人工替代 |

参考内核使用小写错误码与简化 `expected_revision`，对应关系见其 README；它不提供生产事务和分布式幂等。

## 7 更正和删除传播

老师改判追加复核决定，失效旧证据并发布变更事件。消费者重算知识状态，标记依赖旧证据的计划、记忆、上下文和报告过期。原始事件作为历史保留，当前查询仅使用有效事实；对外已发布报告生成更正版本。

历史报告依赖其截止范围内的事实。下个周期正常产生新作答，不使上周期报告自动失效；迟到资料或更正影响截止前事实时才标记相关报告。报告发布需在学生行锁与当前事务下确认没有截止范围内的未处理变更，而非仅比较全局修订号是否相等。已发布历史可带更正标记查看，但不能把失效内容作为当前行动建议继续使用。

“证据只追加”描述业务更正机制，不意味着个人信息永久不可删除。经核验的删除请求需要处理业务记录、对象、检索索引、摘要、缓存及备份恢复流程中的删除清单。审计保留最小必要元信息，不留一份不可删除的儿童原始画像。

## 8 交付文件与检查

- `schema.sql`：生产基础 DDL 与 RLS 边界，正式上线前在目标数据库执行迁移、回滚、跨范围和并发测试。
- `evidence.schema.json`：可校验的证据事件结构，业务关联仍由领域服务检查。
- `evidence.example.json`：符合事件 Schema 的合成样例。
- `learner-profile.example.json`：完整产品档案示例，包含记忆、知识状态、证据和成长记录。
- `openapi.reference.json`：由已实现参考服务导出，不含未实现完整产品接口。
- `backlog.json`：40 条用户故事及验收和依赖，可导入项目管理流程；初始生产状态均为未开始。

正式开发第一周应将完整接口目录转换成经产品、前后端与内容质量人员共同确认的 OpenAPI，补全具体响应、分页、文件限制与字段枚举；以跨端契约测试约束后续变更。
