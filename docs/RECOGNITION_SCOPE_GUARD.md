# 多空作答缺失的负向范围检查

本次修复阻止一种已复现的误放：原观察包含两个明确的填空位置，却只记录一个没有空位归属的数值；两路输出相同，不能据此将整项判对。它不自动补答案、不改变原观察，也不是完整的多空覆盖方案。

## 触发边界

`answer_scope.scope_gap` 只检查 legacy `answer_slot`：题干为纯数字等式链，至少两个等号和两个分开的下划线占位，作答为一个未标位置的数值或分数且状态为 present。检查使用规范化副本，原题干、笔迹、状态及来源哈希保持不变。空格断开的同一段下划线仍算一个占位。

明确带 `#` 空位编号、已经记录多项作答、自然语言题、含变量表达式以及 `question` 协议，不新增此项限制。未命中只表示不属于这个狭窄反例，不能证明读全或读对；特别是漏负号、普通分数误读为带分数、把小数拆开，仍须另行解决。

## 判定与请求

- 同标签两路一致也保留 `target_scope_unverified`，结果为 needs_revision / unable_to_judge。既有等价、非实质差异和视觉复核不能清除这项范围缺口；R1 持久化入口独立复查原观察，不能仅信旧 ready 标记。
- 当前核读接口没有可验证的逐空覆盖恢复契约，因此不为这些项发出必然无法消费的视觉或复核调用。跨标签候选中，只要一整侧都是此类缺口，所有跨路配对都无法放行，语义对齐也跳过。
- 其他题继续原流程。跨标签存在正常候选配对可能时，完整原输入照常送对齐，不筛行、不改来源 ID；原有印刷条件预检仍适用。
- 单独的 `multimodel_audit.scope_dispatches` 保存 `not_dispatched / scope_resolution_unavailable`、协议版本、来源哈希及必要数量，不伪造调用、尝试、用量或自动恢复成功。

## 学习和坐班体验

原图和已记录笔迹保留，提示“本题的作答范围尚未完整核对，原图和已有笔迹已保留，待AI继续核对”。这是一项 AI 未完成工作，不以字迹看不清为由创建老师必审任务，不记为孩子答错或薄弱点，不生成知识证据、标准答案或解法。同页其他有效错题仍进入正常学习记录。当前没有后台自动补齐承诺；下一阶段须先验证逐空证据协议。

## 验证证据

反例来自一次已归档单模型观察的反事实复制：将同一观察交给两个离线 Fake 来源，旧流程放行为 ready/correct，新流程阻止。它不是实际两模型独立共识，也不是人工教研金标准。

候选相关回归 505 项通过，末轮专项 44 项通过；SQLite/PostgreSQL 持久化、既有隔离/对齐和 R1 回归 109 项通过。独立审查另有 11 项边界和 1 项 SQLite 持久化检查通过。这些集合有交叉，不累加为独立用例数。上传 API→Worker→新 API 客户端→学习/老师队列验证：两次模拟首读、68 合成 tokens，无追加范围调用；缺口无学习证据，另一个有效错题正常保留证据。

六页历史首读缓存的 229 条观察、163 条初步结果前后相同：31 条 ready、132 条 pending 均保持原值。此回放没有运行历史付费后续复核，不是整页准确率或时延验证。只读扫描本机 211 个当前模型判对案例，狭窄匹配器命中 0；因此没有自动改写旧记录或批量重跑。

私有证据保存在运行目录的 `scope-gap-integration-20261021`、`scope-gap-independent-offline-20261021`、`scope-gap-current-state-scan-20261021`；正式树验证与激活结果见 [持续交付记录](CONTINUOUS_DELIVERY.md)。本阶段新增真实模型请求为 0，未宣称待核数量减少或整页纠错已达标。
