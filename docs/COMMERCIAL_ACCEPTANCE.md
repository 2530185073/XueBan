# 商用验收口径

最后更新：2026-10-21

本文只冻结当前已确认的范围、判题链路和验收口径。它不把开发记录、合成样本或本机历史照片测试当作商用通过证据。

## 1. 首发教材范围

首发按用户确认的初中、人教版开展。`curriculum/selection.json` 与 `curriculum/official_catalog.json` 中其他年级、学科和出版社是资源候选，不代表全部纳入首发或已经通过商用验收。基本拍照纠错可依据原图进行；教材、章节和知识节点归档必须落在明确的已发布图谱版本内。

学生需明确选择教材并固定 `graph_version`，不能以 `publisher_latest` 自动替换正在使用的书图。当前人教七上 R3 已有官方来源核对和独立 AI 审查，六章、75 个技能；这不等于人工教研或托管点现场版次确认。完整范围及发布门禁见 [教材发布说明](curriculum/GRAPH_PUBLICATION.md)。其他目录的 `publisher_mismatch`、`incomplete` 状态仍须分别解决，不能以有书名代替内容校核。

## 2. 默认判题链路与结果规则

本轮启用 `CORRECTION_MODE=two_model`，对应 `TwoModelWholePagePipeline`，提示版本为 `photo-correction.two-model.v5.2`。两路各自读取整张原图、记录学生实际作答并判题，独立阶段不提供对方内容。模型 ID、接口类型和思考参数均以运行配置为准，本机速度候选使用 DeepSeek 与 GLM；GPT Responses 配置继续支持。

链路为：

`原图 → [独立识读并判题 ‖ 独立识读并判题] → 逐作答目标比对 → 有分歧时按页批量对照原图复核 → AI 候选或待核 → 同一事务保存`

两路独立读取不代表错误在统计上相互独立，也不是人工金标验证。后续复核可见已有候选，不算新增独立赞成票。分歧按目标数和文本预算分批；真实笔迹、印刷细节等问题先做不带候选答案的独立原图补读，再对绑定来源复核，其他直接复核批次可并行。实际判题分歧使用配置的裁决模型。仍无法看清或原文/来源不一致时不放行。缺少第一阶段有效结果、无法消费的范围缺口和部分格式隔离页面不追加这些付费恢复。


可用 AI 候选有两条路径：

1. `matched`：两方成功且对应同一道题/空，有限排版归一化后的题干、选项、实际作答和判定一致，没有未解疑点；错误项还须提供一致的正确答案和改正依据。
2. `reviewed`：AI 对照原图确认仅为转述/格式，或说明差异为何不影响判定；涉及真实笔迹、条件或判定变化时，须提供直接图像依据。学生作答只能选已归档候选原文，不能生成第三种答案；若模型写错来源标签，但回显唯一精确对应另一候选，程序纠正标签并记录来源，不凭相似度创造新作答。数学上应当得到某个数，不能证明被遮住的笔迹就是这个数；仍有关键疑点则不放行。

复核成功后公开 `reason_codes` 与已解决的疑点清空，原始双候选、原分歧、复核输出及处理原因仍保留在私有审计；成功结果为 `origin=model / validity=candidate`。页面与报告仍称 AI 初判，不增加老师确认统计或宣称已掌握。未解决的视觉不清、模型分歧和服务失败分别使用 `visual_unreadable`、`model_disagreement`、`reconciliation_unavailable`，保留待核且不据此形成薄弱点或开启针对性练习。老师求助始终由学生主动选择，不自动创建求助任务。

有限的逐位置算术复算只处理有明确空位编号、完整常数连等式和原文跨度的受支持形式，每一空代回自己的印刷等式。它可在两种既有成功路径应用：全部来源、身份和独立视觉门槛通过的复核；或两路完整首读均成功、既有 matched 门槛通过且都原判正确。后一条要求两份原观察分别核算，印刷结构、逐位置原值和错误结论完全一致，才可纠正两路共同算错；部分格式隔离页面不走此分支。证明某空错误时，保存原学生笔迹，给出该空的错误和应填值，不借用其他空的符号；正确空不另给应填答案。原模型结论与算术依据同时留档，并区分双源或视觉来源。此规则不增加模型请求，不放行缺失证据，不将未知或错误结果自动提升为全对；不支持的形式沿用既有结果。

单选题中 `A` 与 `(A)`/`（A）` 只有在同题号、完整相同题干和完整唯一选项集合、明确 single_choice、两边作答清楚且字母是本题合法选项时视为包装等价。仅接受一个标准大写字母外的一对圆括号和外缘空白；多选组合、解释、嵌套括号、未知选项与数学表达式不扩展此规则。比较不改写原 answer_text 或来源哈希，也不消除其他条件、判定或疑点分歧。

有一方调用失败时，可保存另一方已经读出的内容供核对，但缺少第二份有效结果不构成互证；两方均无可用输出时，任务失败并保留调用记录。超时、格式错误、网络不可用均不等于学生答错。

缺少年级登记、学科标签或已校对教材图谱，不阻塞此整页路径依据原图进行基本纠错。知识归档另行受教材门禁约束：学生年级、学科、出版社、最新版目录和已校对图谱节点须匹配；不具备这些条件时保留作答记录，不编造章节或知识掌握情况。两模型知识点名称交集本身也不能绕过目录核验。

## 3. Worker 落库与恢复

正常整页上传由一个识别任务承载两模型结果；任务完成时，在同一事务保存题目、学生原始作答、每题 `CheckRun` 审计记录、AI Decision 及核验摘要。`CheckRun` 是判定记录，不代表又发起了一次模型请求。已带整页 assessment 的题目不再逐题排入 N 个 `check` 任务，因此一张含多道题的照片不会在整页读取之后再默认调用 N 轮模型。

显式重试、订正复核，以及没有整页 assessment 的兼容识别器仍保留检查入口；不能把这些兼容路径与默认整页调用量混为一谈。每个结果绑定当前题目版本、作答版本和原图指纹，旧任务结果不能覆盖新订正；学科被手动修正时也更新版本并使旧检查失效。

任务领取包括 `queued`、到期的 `retryable_failed` 和 lease 已过期的 `running`。普通任务最多执行三次；是否重试仍由明确错误码和剩余次数决定。R1 原图恢复另有持久派发限制：已预约派发后失联不会自动再发，结果未知保留审计。当前 provider 适配器每次只执行一次请求，不自动重试超时。任务层对限流、上游暂时不可用、并发限制和存储错误保留有限恢复机制；整页聚合为不可用或非重试失败时保留失败状态，后续显式重试是一次新的调用，不能假定上次未计费。

页面关闭或轮询超过观察窗口不代表任务完成。前端将活动任务保存为可恢复的 `waiting` 状态，继续观察或再次打开记录后从服务端恢复。任务状态、题目状态和核验状态分别呈现：任务已成功保存，不等于每道题都已得到确定对错。

## 4. 调用预算、Worker lease 与运行边界

单次请求时限、输出 token 上限和模型路由以运行配置及 `providers/two_model.py` 为准；默认独立首读有 24,576 output tokens 上限，客户端 `max_attempts=1`。复核每批最多 6 个目标，并按文本预算和判题路由进一步分批；一个目标过长仍可能超时或截断。

**每页最多两项复核同时执行，不是全页总共最多两次。** 当前 `BoundedSemaphore(2)` 仅限制并发；180 秒窗口限制何时继续派发，已发请求仍受自身时限约束，也不是页面硬截止。语义对齐、普通复核、独立补读、关键印刷补读及其后续复核均可能产生实际调用，所以不能承诺每页固定 2—4 次或用批次数代替计费请求数。应读取真实 `Metadata.attempts`、usage 和归档阶段记录；零派发不能伪造调用或用量。

[逐空恢复计划](RECOGNITION_SCOPE_RECOVERY_PLAN.md) 中“读回 1 次 + 复核最多 1 次”是尚未启用的新恢复分支设计，不是现有整页总调用保证。未来全页持久上限需显式冻结政策、扣除已派发与未知状态，不能只靠内存并发信号量或模型声明证明预算。

Mac 的 `configure-models --mode two_model` 会把该运行配置的 `WORKER_LEASE_SECONDS` 设置为至少 **600 秒**；其他部署入口须检查实际注入的运行值，不能把本地配置脚本的行为当成所有环境已生效。推理期间 worker 通过独立短事务 heartbeat 续租，通常每 30 秒一次。续租和最终提交均受 lease token、任务状态与过期时间约束。

Heartbeat 正常且数据库、进程可用时，lease 会延长；进程休眠、崩溃、数据库持续不可用或续租长期失败，仍可能导致新 worker 领取同一任务。旧执行的提交受 token/输入版本围栏限制，但供应商端已经发出的请求不一定能撤销，仍可能产生重复计费。当前实现未提供供应商跨进程调用恰好一次的保证。

不因 timeout 自动重试，能降低无意识的重复付费；它不能消除 lease 恢复或用户显式重试产生的新调用。真实网络下的超时、进程中断、续租失败、恢复和重复计费边界仍需演练，不能由离线测试代替。

## 5. 完成状态与验收观察

验收需要分别统计“任务完成”“已给出 AI 候选判定”“待核”“失败”“可能漏项”，不能把一个 succeeded job 当作整张作业全部判完且无错。

以下情况不构成整页有效判定完成：

- 任一原图仍有活动任务，或前端只恢复到 `waiting` 状态；
- 两次整页读取缺项、题号/填空对应失败，或学生笔迹/判定差异经过复核仍未解决；
- 一方超时、输出无效，另一方的内容虽被保存但仍缺少独立印证；
- 某题作答识读为 `pending / failed / needs_revision`，或 Decision 为 `unable_to_judge / needs_review`；
- 数据已落库，但前端读取 Job、HomeworkSession 或 CaseDetail 时未通过契约校验。

如果任务结束且保留了明确待核项，应向学生说明“处理已完成，部分题目需要核对”，而非无限转圈、默认为做错或宣称全对。整页模型可能同时漏掉某些题；两个模型都没有输出的题无法仅靠输出一致性发现，所以当前 coverage 保持保守口径，不承诺“本页全部题目已识别”。

“服务返回格式不符合契约”应排查响应 JSON/Schema、空响应、前后端版本以及 `failure/result` 组合，不能解释为学生作答错误。模型输出审计、任务记录与页面展示应能沿同一个原图、作答和题目版本追溯。

### 5.1 本轮实现范围与未验证部分

当前代码以两模型整页独立读取和判题为主路径，确定性比对保留分歧，并在整页完成事务保存判断；同时保留原始作答、后续订正及 AI/老师证据来源。待核项不形成确定薄弱证据；新订正不会仅因替换当前作答就删除此前真实发生的错误记录。

上述为实现规则，不是商用效果结论。本文件不填入尚未确认的测试总数、真实联网耗时、成本或准确率。工程回归、实际配置和联网结果由对应测试记录补充；只有固定人工金标集上的独立评测才能回答误放行率、漏判率与覆盖率是否达标。

## 6. 商用验收门槛

验收优先级是“人工金标错题被放行成正确”的误放行率，其次才是漏判、覆盖率、延迟和成本。数值必须区分：

- **建议值**：尚未在冻结金标集上实测，只能作为发布门槛建议；
- **已测值**：明确数据集、照片分组、模型版本、提示版本、日期、分母、分子和失败样本后得到的结果。

没有人工标注金标集、独立保留集和固定分母，不得报告“准确率”“商用准确率”或“通过率”。阈值应在查看保留集结果前冻结，并按年级、学科、题型、手写清晰度、图形/表格、单位/多空和服务失败分别切片。

本机“习题分类”照片和历史照片有开发、调试和回归使用历史；即使模型当前表现良好，也不得宣称模型从未见过这些图片。商用评测应建立授权的人工 gold 集，并分离开发集、调参集和冻结保留集。

使用 `commercial_eval` 进行评测时，验收报告至少应包含每题人工结论、模型结论、是否放行、是否服务失败、审核轮次、证据是否充分、错误类型和可重试状态；报告必须把模型输出与人工金标统计分开，不把模型自述概率当作验收指标。

## 7. 当前结论

当前采用两路并行、互不读取对方输出的整页识读和判题；本机速度配置为 DeepSeek 与 GLM。格式和表述差异先由 AI 对照原图批量消解，实际笔迹分歧先独立只读再进入绑定来源的复核，其他直接复核批次可并行。清楚且匹配或复核通过才形成 AI 候选，未解决的冲突、缺项或调用失败保持待核。整页 assessment 直接落库，正常上传不再追加逐题模型检查。基本纠错与教材知识映射分别处理：缺少学籍不会阻断前者，后者仍须通过目录和图谱范围核验。

任务具备 lease、heartbeat、token/输入版本围栏、有限恢复和失败留痕，但并未消除供应商侧重复调用风险。当前仍缺少足以宣称商用通过的冻结 gold/holdout 结果、多学科真实照片稳定性与完整失败恢复演练；目录元数据齐全也不等于正式知识图谱已逐项校对完成。不能将模型已配置、单页联网成功或离线回归通过表述为全部验收通过。
