# 商用验收口径

最后更新：2026-10-20

本文只冻结当前已确认的范围、判题链路和验收口径。它不把开发记录、合成样本或本机历史照片测试当作商用通过证据。

## 1. 首发教材范围

首发范围以 `curriculum/selection.json` 和 `curriculum/official_catalog.json` 当前已有记录为准。只覆盖项目方明确提供年级、学科和出版社的组合，教材版本按 `publisher_latest` 处理；未在目录中明确匹配的年级、学科、出版社或版本不进入判题知识范围。

当前范围包括：五年级、六年级、初一（七年级）、初二（八年级）已有选择表中的学科及出版社。目录中的出版社元数据只是范围和版本候选，不等于已经逐章、逐节、逐知识点完成教研校核；教材版本无法确认时不得编造章节、知识点、答案或解法。

五年级科学的选择表记录为科学教育出版社，但当前官方目录状态为 `publisher_mismatch`；在该状态被教研或产品确认前，不得宣称该学科的知识点范围已经可商用。五年级艺术音乐等目录状态为 `incomplete` 的组合同理保留为待验收，不以有书名或候选版本代替内容校核。

## 2. 判题链路与审核规则

目标链路固定为：

`DeepSeek 首轮判题 -> GPT 兜底/复核`

后续审核按门禁触发：DS 首轮判为 `correct` 的结果必须交 GPT 复核；DS 出现 `primary_slot_conflict`、首轮失败、实质疑点、复杂题型或缺少错误题答案/改法时也升级 GPT。GPT 是第二层终审，不再设置第三层模型。提示版本固定为 `photo-correction.v19-two-stage-review`。

“正确”放行必须同时满足：

1. DS 和 GPT 的有效结论一致为 `correct`；
2. GPT 已核对题干、学生作答、图形/表格/单位和参考推理，证据充分且没有未解决的识别缺口；
3. 必要时逐空核对，不能用整题文字相似替代逐项判断；
4. GPT 输出了足够的判定依据，且不缺少错误题所需的 `correct_answer` 与 `correction_method`。

未满足以上条件时，不得绿色放行为确定正确。两模型一对一分歧时也不得放行 `correct`：如果 GPT 明确判错且同时给出充分的正确答案和改法，可以输出红色 `*` 的错误结果；如果 GPT 无法确认、缺少正确答案或改法，或两模型分歧无法由证据消解，必须输出 `unable_to_judge`/`needs_review`，保留重试路径，不得猜测为错题，也不得生成未经依据支持的纠正内容。系统不展示或依赖模型概率估计。

服务失败、超时、格式错误、网络不可用或审核未完成，不得直接判为错误。应保留原图、失败记录和可重试状态；只有明确的模型判题结论才允许进入对错结果。

## 3. 当前 Worker 只读审查结论

当前实现中，一个识别任务成功后，会在同一完成事务里为每道题创建独立的 `check` 任务。整页识别成功不代表整页判题已经完成；题目较多时，前端需要继续观察全部 check jobs 和每道题的 case 状态。

任务领取包括 `queued`、到期的 `retryable_failed` 和 lease 已过期的 `running`。单任务最多执行三次。限流、上游暂时不可用、并发限制和存储错误可在次数未达上限时自动重试；Provider timeout 不自动重试，因为请求可能已经计费。非重试失败会进入 `failed`，保留失败记录和审计尝试，并将识别/判题对象恢复到需要重试或人工核实的状态。

前端单次最多轮询约 600 秒；到达上限仍有 active job 时，保存为 `waiting` 并提示“任务仍在处理中”。这是可恢复的处理中状态，不是成功，也不是判错；页面保持打开时还会继续自动观察，用户也可以稍后重新打开记录。

## 4. 两阶段审核与 Worker lease

当前默认 `WORKER_LEASE_SECONDS=300`。推理期间 worker 每 30 秒独立事务续租，续租只接受仍持有原 lease token 且尚未过期的执行；提交结果时还会再次检查 token、状态和过期时间。因而：

> 当前审核最多包含 DS 与 GPT 两个 provider 阶段；单次 provider 时间预算不能直接等同于整条任务的墙钟时长。Heartbeat 正常、数据库可用且 worker 进程持续运行时，lease 会持续向后延长。

仍需结合 DS/GPT 阶段和本地开销做长任务恢复验证。若 heartbeat 线程无法调度、数据库连续不可用、进程被暂停/休眠/崩溃，或续租失败持续超过 lease 周期，新 worker 可以重新领取同一个任务。旧 worker 的最终提交会被 token fence 拒绝，通常不会重复写入业务决策；但是旧 worker 已发出的 DS 或 GPT 请求可能与新 worker 并行，造成重复调用、重复计费和供应商侧副作用。

当前单个 DS/GPT provider call 的预算为 200 秒，HTTP/Provider 校验上限为 240 秒；这不是整条 pipeline 的总预算，仍要加本地处理开销。本文不把模型已配置、单次调用成功或离线测试结果表述为线上可用或商用验证通过。

不应只把单个 Worker 任务拉长并依赖 heartbeat。建议拆成持久化阶段：DS 首轮完成并落库，GPT 复核完成并落库，最后由一个短的聚合阶段提交结果。每个阶段都应有独立状态、重试预算、幂等键、供应商请求审计和明确的最终失败终态。这样可以缩短单次 lease 持有时间，也能避免一个长调用阻塞整条任务链。

## 5. “未跑完所有结果”类问题的验收解释

以下情况不能视为整页完成：

- 识别 job 成功，但仍有 check job 处于 queued/running/retryable_failed；
- 某道题 answer recognition 为 pending/failed/needs_revision，且没有足够的作答文本；
- Provider timeout、invalid provider output 或审核服务失败导致该题没有有效 decision；
- 前端轮询到达上限，只拿到 active job；
- 任务虽已写入数据库，但前端读取 Job、Accepted、HomeworkSession 或 CaseDetail 时不符合契约。

“服务返回格式不符合契约”首先应按响应 JSON/Schema、非 JSON 空响应、前后端契约版本不同或状态与 `failure/result` 组合不一致排查，不能把它解释成模型判定错误。当前前端对成功响应和 Job 状态有严格 shape 校验，因此任何不完整 DTO 都会停止本次处理；这保护了错误数据不进入学生页面，但也会让服务端兼容性问题直接表现为该提示。

### 5.1 Pipeline 审计修复现状

以下为主线程提供的最新修复状态；本轮只更新文档，没有重新启动 worker，也没有做修复后的独立回归验证：

1. DS 的 `primary_slot_conflict` 现在会升级 GPT，避免首轮逐空/槽位冲突绕过必需复核。
2. 归并时只要出现 green/non-green 矛盾，就保留在 `uncertainties`；禁止把 `wrong` 归并成 `correct`。两模型分歧不得放行 `correct`。
3. GPT 无法确认、缺少正确答案或改法、服务失败或审核未完成时，结果改为 `unable_to_judge`/`needs_review`，不生成纠正内容并保留重试路径。只有 GPT 明确判错且证据充分时，才可带红色 `*` 输出错误。
4. 先前只读审计没有确认审计 attempts 丢失：DS/GPT 调用记录仍能合并保留。本文件不以历史回归记录替代线上或商用验证。

## 6. 商用验收门槛

验收优先级是“人工金标错题被放行成正确”的误放行率，其次才是漏判、覆盖率、延迟和成本。数值必须区分：

- **建议值**：尚未在冻结金标集上实测，只能作为发布门槛建议；
- **已测值**：明确数据集、照片分组、模型版本、提示版本、日期、分母、分子和失败样本后得到的结果。

没有人工标注金标集、独立保留集和固定分母，不得报告“准确率”“商用准确率”或“通过率”。阈值应在查看保留集结果前冻结，并按年级、学科、题型、手写清晰度、图形/表格、单位/多空和服务失败分别切片。

本机“习题分类”照片和历史照片有开发、调试和回归使用历史；即使模型当前表现良好，也不得宣称模型从未见过这些图片。商用评测应建立授权的人工 gold 集，并分离开发集、调参集和冻结保留集。

后续新增 `commercial_eval` 评测脚本，至少输出每题人工结论、模型结论、是否放行、是否服务失败、审核轮次、证据是否充分、错误类型和可重试状态；报告必须把模型输出与人工金标统计分开，不把模型自述概率当作验收指标。

## 7. 当前结论

当前工程具备任务 lease、heartbeat、token fencing、有限重试和失败留痕的基础；它可以降低旧 worker 覆盖新结果的风险，但不能消除长任务期间重复外部调用的风险。DS→GPT 两阶段规则已在本文冻结：DS `correct` 必须交 GPT，GPT 无法确认或缺少纠正依据时不得猜测；两模型分歧不得放行 `correct`，GPT 明确错误且证据充分时才允许带红色 `*`。冻结 gold/holdout 评测、真实照片稳定性、阶段化任务和失败恢复演练仍待完成，不能宣称模型线上可用或已达到商用验收。
