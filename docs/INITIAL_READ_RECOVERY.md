# 整页初读的中断恢复

此功能防止已完成初读丢失后从头请求模型；不提高识图准确率，也不保证所有中断都能继续。
项目默认关闭。本机是否开启及验收记录以 [持续交付记录](CONTINUOUS_DELIVERY.md) 为准。

## 启用条件与范围

Worker 设置 `INITIAL_READ_RECOVERY_ENABLED=1`，同时满足 `READ_CHECKPOINT_ENABLED=1`、
`CORRECTION_TARGET_UNIT=answer_slot`、`STRUCTURE_NAVIGATION_ENABLED=0`，并且所有参与角色的
适配器 `max_attempts=1`。条件不符时不取得派发许可，不能用增加适配器重试次数规避限制。
模型密钥仍只在 Worker；学生网页无需新增开关，沿用首路草稿入口。

仅首次合法执行、尚未发布题卡的普通 `recognize_homework` 初始化恢复记录。新照片订正、
原图 R1 重核、单题检查、旧终态任务都不进入。已有题卡的作业若明确发起一项全新任务，
继续原有流程；这不表示该新任务获得恢复能力。旧任务有未知执行历史却没有完整记录时，
不能被重新认定为“尚未请求”。

已有恢复记录后关闭此开关、切换协议/模型/密钥或变更原图，都不会回退到从头付费流程。
这里没有“自动换模型”“为旧失败任务补建结果”或新派发额度。

## 一份私有记录，固定请求次数

沿用 `Task.audit.recognition_draft_checkpoint`，版本为 `recognition-draft.initial-resume.v2`；
没有新任务系统或缓存表。每张图的 primary、secondary 各有一个固定槽。

| 状态 | 后续行为 |
| --- | --- |
| available | 在短事务中保存唯一许可并提交，之后才调用模型 |
| reserved | 已获许可但没有可靠终态；进程丢失后结果未知，不自动重发 |
| completed | 原始完整响应和元数据安全保存，可在全部绑定相同且重新校验后复用 |
| failed / unknown | 保留收据及已知诊断，不自动重发 |

发前许可是本地主机限制，不是供应商幂等键，也不证明实际请求已发送或已收费。许可提交
之后、HTTP 之前中断也会保守停止。完整响应未成功保存时，不能拿公开三字段草稿补造它。

复用必须匹配学生、任务、作业、原图顺序及字节、模型配置、提示词、Schema、协议源码等。
密钥通过任务/角色作用域 HMAC 检查变更，私有记录不保存密钥明文，也不把摘要发给模型。
原始选项、作答状态、字符串与来源摘要保持不变；复用来源不冒充一次新的独立观察。

一份完整来源已保存，另一份尚未预约时，只调用后者；两份都已保存时可零次首读重发。
但只要已开始后续语义配对、视觉核读或复核，本版便不在中断后继续重放该任务。每个后续
付费入口先保存此状态；同一正常执行中，一页失败不会阻断其他页的复核。

公开进度仍只显示题号、题干与作答原文，不暴露收据、费用、完整响应或预先判定。
未完成草稿不进入学习证据、知识薄弱点或家长报告。最终应用仍使用原事务和版本检查。
原收据保留原用量，复用执行不产生虚构 HTTP Attempt 或重复计入该来源用量。

## 失败与验证边界

结果未知会停止本次任务，原图保留。前端目前沿用通用失败文案，允许学生明确选择重试；
此功能不增加自动重试。已有题卡的失败任务不被自动改写，也不能认为老师必须逐题核实。

回归使用真实 HTTP 适配器、数据库迁移及 `httpx.MockTransport`，验证许可前后中断、
保存一/两份来源、落盘失败、后续阶段中断、旧执行者迟到、配置变更和公开数据隔离。
另比较正常首次执行的 HTTP body、调用数与结果，保持请求语义不变。它们属于工程与故障
验收，不代表真实供应商中断恢复、识图质量或更低账单已得到现场验证。

PostgreSQL 支持并发 Worker；SQLite 仅为单 Worker 测试替身。既有 SQLite 通用领取路径
在两个 Worker 同抢过期任务时可能抛出 `database is locked`，本次没有修改该路径；独审
保留该失败记录并另验 PostgreSQL 的单胜者及零重复请求。
