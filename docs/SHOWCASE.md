# 展示账户与讲解稿

一个**完全虚构**的演示学员，用来讲解学伴的知识图谱。所有数据都是编的，没有真实学生、没有真实照片、没有调用任何模型。

- 学员显示名：**演示学员（虚构数据）**，位于独立的运营方 `demo_showcase`，不会和任何真实学员出现在一起。
- 账号密码**不在仓库里**。创建时随机生成，保存在本机 `~/.local/share/xueban/local-dev/demo-showcase-accounts.json`（权限 0600），清单见 `~/.local/share/xueban/demo-accounts-20261022.md`。
- 入口：学员 `http://127.0.0.1:8000/learn/`，老师 `http://127.0.0.1:8000/staff/`。

## 数据是怎么来的

脚本 `services/backend/scripts/seed_showcase.py`：

```sh
cd services/backend
.venv/bin/python scripts/seed_showcase.py plan     # 只打印故事分布，不写任何东西
.venv/bin/python scripts/seed_showcase.py seed     # 写入（已写过会直接退出，可重复运行）
.venv/bin/python scripts/seed_showcase.py verify   # 打印算出的状态分布
```

只写**原始事实**：作业、图片、题目、作答、检查、判定、知识点关联、独立完成的老师确认。
**不写**学习证据和知识点状态：这两样由系统真正的投影规则算出来（`project_student`），所以图谱上看到的颜色，是规则算的，不是画的。
有测试保证这一点（`tests/test_seed_showcase.py`）。

## 图谱讲了什么故事

人教版七年级上册共 75 个知识点，6 章，每章故事不同：

| 章 | 形状 | 讲什么 |
|---|---|---|
| 01 有理数 | 7 个全部较稳 | 基础扎实 |
| 02 有理数的运算 | 8 稳 / 2 巩固 / 3 需再看 | 核心很强，但**除法里的符号**和**乘方**是弱点 |
| 03 代数式 | 6 稳 / 2 巩固 / 1 需再看 | 整体不错，负数代入的括号常错 |
| 04 整式的加减 | 4 稳 / 2 巩固 / 2 需再看 | **去括号**不稳，其余良好 |
| 05 一元一次方程 | 5 稳 / 7 巩固 / 1 需再看 | 当前正在学，大量在进行中 |
| 06 几何图形初步 | 3 稳 / 5 巩固 | 刚开始，多数还没到 |

合计：阶段性较稳 33 · 正在巩固 18 · 需要再看看 7 · 还不判断 17。每个有记录的点，背后有 1 到 4 次老师核实的作答。

## 5 分钟讲解稿

**1. 开场（先别点任何东西）**
> 这是一个学生的知识地图，不是分数表。每一个亮点是教材里的一个知识点，亮不亮取决于有没有真实的作业记录证明他掌握。
> 绿色是阶段性较稳，蓝色是正在巩固，橙色是需要再看看。暗的是还没有记录，**没有记录不等于不会**。

**2. 看结构**
> 六个星团是六个章节，旁边的小数字是这一章里各状态的个数。虚线是知识点之间的前后依赖：学这个之前要先会那个。

**3. 找弱点（点橙色的星，例如「有理数运算顺序」）**
> 点开能看到它的状态和原因，下面是**证据**：哪一天、哪次作业、哪道题、当时做对还是做错。
> 点「查看原题与订正」，回到**当时那一页的原照片**和孩子写的原话。这样老师和家长看到的每个结论，都能回到孩子真实写的东西。

**4. 看依赖**
> 选中后，和它有前置关系的星会亮起并有光流动，能一眼看出「是不是前面的基础没打牢」。

**5. 看趋势（点绿色的「改善中」点）**
> 同一个知识点，先错、改正、再独立做对，不同日期、不同题型，系统才算它「较稳」。一次做对不够。

**6. 收尾**
> 我们**不打分、不排名、不催孩子**。这张图只回答一个问题：现在最值得陪孩子花时间的是哪几个点。老师和家长拿它去线下沟通。

## 讲解时的几个提醒

- 说清楚这是**虚构数据**，别让听众以为是真实学生。
- 图上「较稳」是系统根据规则判断的，**不等于已经掌握**，页面底部也这样写。
- 如果有人问「这些判断准确吗」：演示里的判定是**编的**；真实使用中，AI 初判在老师确认前一直只是初判。真实手写作业的识别质量还没有通过验收，这一点不要夸大。

## 清理或重建

演示数据只属于租户 `demo_showcase`。系统里删除学员的正规做法是**数据治理删除申请**
（`POST /v1/students/{id}/deletion-requests`，须由具备「数据治理」角色且被授权该学员的账号提交，由 Worker 执行，
会连同学习层下游记录一起清除；流程见 [OPERATIONS](runbooks/OPERATIONS.md)）。

- 演示老师账号**没有**数据治理角色，不能自己提交删除；需要另给一个有该角色并被授权的账号。
- 我**没有**实际跑过这条删除流程来清理演示数据，所以「清理后能完全干净重建」目前**未验证**。
- 不要直接用 SQL 删表里的行：外键、学习层投影和删除清单都要一起处理。
- 脚本对已存在的演示学员会直接退出（`already_seeded`），不会重复写入；要重建，先走上面的删除流程。
