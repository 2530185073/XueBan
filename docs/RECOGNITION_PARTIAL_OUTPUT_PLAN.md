# 整页服务格式失败的逐项隔离

状态：下一阶段设计，尚未实现或启用。沿用严格的整页识读和证据绑定，不新增付费复核。

## 已确认问题

P02 的生产协议多视图请求返回 HTTP 200，却因 `items[11].answer_text` 的 `anyOf`
校验失败而整路丢弃。目前失败候选正文未归档，不能判断具体值、可保全题数或识读准确率；
也不能声称修复后可恢复这个历史响应。已有单项 `answer_status_mismatch` 保护在整页
schema 校验之后，无法处理这个失败。

## 实现边界

1. 保留完整 schema、严格 JSON、完整结束与密钥检查。仅整页初读可进入显式的失败候选
   通道，候选只留在受控私有对象；日志、异常 repr、公开 API 不包含正文。坏 JSON、
   冲突重复字段、截断、传输失败或密钥回显继续整路拒绝。
2. 先验证页壳与数量上限，再逐项按原 schema 校验。有效项原样保留，失败项记录固定
   原因、源序号和可验证身份；不把数字转成字符串、不截长答案、不用正确答案补学生作答。
   重复规范题号的整组隔离，不保留任意第一项制造唯一性。坏项无身份时只记录页面缺口。
3. 双路各自有效且可绑定的题才走原有核对。只有单路有效的项保留真实观察并明确标注
   “另一路本页识读部分未完成”，不得宣称两路一致或计入知识图谱。
4. 新原因归类为服务输出未完成，不能显示成字迹不清。页面覆盖说明使用“未完成返回项”，
   不臆测题数；R1 的目标题失败时保留旧记录，其他题有效不代表本题恢复成功。
5. 使用默认关闭的实验选项；首先以已归档有效响应作离线故障注入。后续自然新上传遇到
   schema 失败时可私有归档 assistant 最终结构化内容，供同响应复放，不保存 reasoning
   或完整 envelope，也不为补历史缺失正文重发付费请求。

## 验收

- 一坏项加多好项：只保全真实有效项；两路均有效才能成为可用证据。
- 页壳坏、无题号、坏题干、重复题号、跨页和导航冲突：不造题、不串来源。
- R1 目标题坏、双方同项坏、全部项坏：明确未完成且不替换原记录。
- 截断、坏 JSON、冲突重复字段、密钥：仍整路拒绝且不泄漏正文。
- 调用数不增加、usage 只记一次，刷新后缺口提示保持，不新增无依据学习证据。

完成离线验证后，才决定是否在新的真实上传上开启对照；结果与已付费的 P02 历史失败分开报告。
