# 逐空作答范围恢复：下一阶段协议计划

状态：已完成私有、离线、不可放行的引用验证原型；本文保存下一阶段计划。原型未接入生产、未发模型请求。正式系统仍采用已部署的范围缺失负向门；本原型任何输出的 `eligible_for_release` 都为 `false`。本轮 P02 两次已付费实验已止损，不再用相同原图叠加提示词或判题请求。

## 要解决的具体缺口

旧输出可能把两个空的完整题干和一个末空答案包装成整题正确。负向门已阻止这类结果进入正确结论，但还不能自动补齐原图证据。本设计只探索其窄范围：原输出中的纯数字连等式、多个明确分离的占位、没有独立 `#` 空位标签。普通多空文字题、证明过程、表格、整页拆分和 R1 版本迁移都不在本原型内。

引入结构化范围记录的目的，是让后续 AI 原图复核能指出每个作答位置对应哪段新识读。它不把下划线、整数、`coverage=complete` 或模型共识当作原图事实，也不按数学正确值补写学生笔迹。

## 最小数据契约

主机冻结：原图 ID 和内容 SHA256、当前输入版本、每题 opaque `target_key`、定位信息、两路原始源的完整记录。冻结内容参与摘要。已有源不改写、不补号、不替换 `answer_text`；新观察另行归档。两个旧记录存在不意味着它们拥有独立判题证据，原型没有增加判题票。图哈希目前由调用者传入，原型不读取像素或请求字节；未来 harness 必须从实际发送的图像字节计算并核对，不能信任 provider 回填的哈希。

一次盲视觉请求只带原图和 `target_key + locator`。定位只允许正式 `visible_locator` 的印刷题号和区域字段；题号必须规范化为本范围支持的数字层级并与两份原始源题号一致，请求只发送规范题号。全角数字、括号等排版可兼容，但自由文本、另一个题号、夹带旧答案均拒绝。不能附带旧答案、旧题干、判断、正确答案或旧源的槽位数量。现原型没有 provider 调用入口。

每个新观察保留原有 label/stem/options/answer/status/uncertainties/visible_locator，新增可选的 `scope_observation`：

```json
{
  "coverage": "complete | partial | uncertain",
  "targets": [
    {
      "printed_ref": {"text": "新题干中的原样定位引文", "occurrence": 1},
      "answer_status": "present | blank | unclear",
      "answer_ref": {"text": "本次新 answer_text 中的原样笔迹引文", "occurrence": 1},
      "uncertainty": null
    }
  ]
}
```

`blank/unclear` 可以没有答案引文；`unclear` 必须保留原因。结构不要求“第 N 空”中文模板。引文 occurrence 仅定位原文中重复出现的相同片段，不代表第几个真实空。主机转换为原始 Unicode 文本跨度；原文不规范化。相同数值在两个位置必须各有不同原文跨度，不能拿同一段文本复制两次，也不能借另一来源或期望答案凑足。

新源摘要绑定原图、冻结请求、目标和完整观察（含引文映射）。正式接入时必须把这项结构纳入既有 source_id/源绑定字段；只新增一个没有参与源摘要的 JSON 字段不够。

## 原型实际验证了什么

- 冻结输入的基本形状、题目键唯一、图哈希和输入版本摘要；冻结后修改调用方对象不改历史快照。
- 每个引文确实出现在本次观察的相应字段；在窄数字形状中它只能覆盖一个文本占位，不能用覆盖两个位置的整题引文代替位置关系。
- 不同位置不能复用同一段答案文本；缺项、重复目标、未知目标、不可解析项均不能变成当前题的有效结果。
- 非字典行、坏 observation/scope/targets 不会拖垮好邻居；未知项不能消耗已知项的位置预算。页错误、单项错误和预算错误返回相同外层结构。
- 数学过程、证明文字、连续下划线不会仅凭字符数量自动生成槽位。形状判断复用正式窄门；引文始终用原始文本跨度。
- 原图/题号/题干/选项不一致、范围未覆盖或明确不确定时保持 AI 未完成。

符合上述机械条件也只到 `pending_scope_review`，永不 ready。测试明确放入了自洽但可能完全编造的笔迹，以及把 `0.3` 的字符切成两个片段的反例：引用一致不能证明原图确实有两份独立笔迹。这里不加猜笔迹的正则去掩盖这个限制。

## 真正恢复前仍必须实现的边界

未来调度上限是同页聚合 **1 次新增盲视觉读回 + 最多 1 次原本尚未派发的复核**，合计最多 2 次阶段调用，不按题逐次调用，不再叠加旧 alignment/visual/review，不自动重试。设计容量为最多 6 题、24 条位置记录。两个输出须按真实请求分别记 usage，不能把两次算成一次。

**这些是设计上限，不是本原型已执行或已验证的预算约束。** 原型只返回 `dispatch_budget_enforced=false` 和上限声明，没有请求台账、预算占位、并发锁、剩余截止时间检查、provider 计费、重试防重或调度器。

在允许实际调用前，主机需要完成一次性派发/重放台账以及输入版本 CAS；复核预算已经用过、剩余时间或 token 额度不够时停止，不开启第二套预算。读回结果晚到、原图/题目/识读版本已变，只可归档历史，不应用到当前结论。

真正 ready 必须经过原图复核：对每个观察位置明确核对其印刷目标、笔迹、位置关系及覆盖范围，并绑定新源摘要和原始图像。复核只能针对已保存的原始引文给结论，不能重新推断、改写或“修正”学生答案。复核发现此前抄写不完整/不实，应返回未完成，不能在判题字段中静默补字。模型是否真的看对图仍需独立的人标/真实样本验收，无法由引用校验器证明。

本原型尚无可消费的 typed 复核输出协议，也没有 ready 发布接口、CAS、知识投影或事件持久化测试。不能让调用者传一个布尔回调来绕过原图核对，不能把同一新观察复制成双来源共识。

## 产品与数据约束

成功后应沿用同一道原题和本次作答，逐位置结果作为证据明细，不增加学生作答次数或独立掌握次数。失败是“AI 尚未核对完整，其余结果可先看”，不自动增加老师待办、不诊断字迹模糊、不记学生薄弱点。不显示虚假的“正在重试”：若没有实际排队任务，明确显示未完成状态。真实可见字迹不清继续走既有明确证据的处理政策。

后续最小接口改动预计为：视觉源的可选范围字段及其源摘要绑定、单页一次调度凭证、原有复核契约的原图范围验证字段、明确版本 CAS；成功投影可复用现有 answer_checks 显示结构。不能复用会重建 aggregate answer_text 的旧 answer_slots 拼接路径。R1 与已保存题目改 target_unit 的问题另行设计，不能作为本轮附带改动。

## 验收与停止条件

现有离线测试覆盖：换行/分号等自由原文格式、重复同值不同引用、复制引文、借旧源/答案、重复/缺失/未知目标、坏类型局部隔离、图/版本变更、改题干或造 # 标签、空白与不清楚、数学过程误作多空、Unicode 定位、上限及结果 shape。所有结果仍不可发布。

下一阶段先审查可消费协议和真实调用预算/CAS，不先发模型请求。通过后用未重复的独立样本和逐位置人标验收，记录错读、漏位、错误 ready、未完成率、真实调用数、时间与 tokens。改善必须是正确完整证据增加，不能仅以待核数量下降或两模型一致衡量。发现任何关键笔迹被补写、遗漏位置仍 ready、来源混用、越预算/重复请求，即停止该候选；不得连续对同页改提示直到“通过”。当前没有任何新增整页准确率或加速结论。
