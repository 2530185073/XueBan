# 完整网页版交付路线

决策日期：2026-10-17。项目负责人明确：**先在网页端完成全部业务内容，网页端实际使用并完善后，再移植 App。**

本文件给出当前路线与下一批工作包；正式范围和发布门槛见 [PHASE1](../PHASE1.md)，任务状态统一记录在 [phase1-backlog.json](../blueprint-v3/contracts/phase1-backlog.json)。本次调整的是交付顺序、任务范围与验收口径，没有新增运行功能，也不构成 C0/R1/R2 放行。

## 1. 本轮交付目标

第一阶段交付完整网页版学伴：学生、坐班老师、管理员、家长都能通过网页完成各自业务。拍照纠错仍是学生主入口；知识图谱、长期 AI、举一反三、预习小测、每日反馈和半月报告均在本轮网页范围内。允许分批开发和受控试用，R2 交付时所有声明的网页模块须完成联合验收。

第二阶段移植 App：共用账号、固定学生身份、业务 API、照片、作答、图谱、记忆和报告；补齐原生相机、系统权限、离线与后台能力、签名分发和升级。Android 已有工程继续保留，其设备特有验收在 App 阶段执行。

“完整”按已确认业务、首发教材/题型和设备浏览器清单验收。题型或内容没有验证时保留待核实/求助，不把功能范围完整解释为所有年级、所有题型均已可靠支持。

| 使用者 | 本轮网页内容 | 任务入口 |
|---|---|---|
| 学生 | 账号登录、拍照/选图、多页处理、检查、提示、订正再检、求助、历史与证据时间线、知识地图、长期 AI、偏好目标、举一反三、预习与自愿小测 | P1-02～08、P1-11、P1-13；W1-02、03、05、06 |
| 坐班老师 | 复核队列、原图和识别核对、接单、改判、重切/拆合、学情及证据映射、记忆核实、题库审核、每日反馈和半月报告 | P1-09、10；W1-02～06 |
| 管理员 | 学员与老师开户/重置、校区授权、学员教材与进度档案、已授权学情和服务指标、数据管理与运维交接 | P1-02、12、14～16；W1-01 |
| 家长 | 手机网页阅读每日反馈和半月报告，查看实际作业、订正、帮助条件、解释范围及更正记录 | W1-04 |

## 5. 真实评测与质量放行

### 样本与标签

1. 冻结首发年级、在用册次/修订版、题型与图像条件；准备获得授权的自然作业。
2. 按原题、题族、同页和重拍关系分开开发、校准、保留集；订正与原作答保持关联，不能跨集合泄漏。
3. 学科审核者标出预期题目/小问/答题空、原始题干和作答、区域、正确性及可确认的首错；有争议的标签经复核，仍未知则单列。
4. 覆盖正确题、真实错题、等价解、缺步骤、涂改、模糊、错误订正、漏图和服务失败；自然分布与专门难例分别报告。
5. 阈值用开发/校准信息形成，并在查看保留集结果前冻结；保留集只用于候选发布验收。

当前 check/recheck 重放已实现，识别/切题与真实端到端评测仍需补齐。模型端的“错误放行”是错误的判对候选；当前正式学科结论仍须老师确认。两者分别计分。

| 指标 | 分母或审查口径 |
|---|---|
| 题目与答题点覆盖 | 人工预先标注的实际答题点；漏切、重复和合并单列 |
| 识别忠实度 | 可定标的文字、公式关键符号与题答绑定；无法确认保持未知 |
| 正确题误伤 | 金标正确却被要求订正 / 金标正确题 |
| 错题误判正确 | 金标错误却被判正确 / 金标错误题 |
| 错题漏检 | 未得到需订正候选 / 金标错误题；失败、漏切、拒判分列 |
| 订正错误放行 | 仍然错误的新订正被判通过 / 仍错误的订正 |
| 错步与提示 | 可确认首错位置、误导、泄答及帮助条件逐项审查 |
| 时延与工作量 | 提交到结果、排队、供应商处理、再检、老师接手及复核工时分别记录 |

现有 `max_regression=0` 只限制相对基线退化；它不是绝对零错误率。现有 `min_slice_denominator` 也不自动满足正式发布的样本和置信要求。每个上线切片同时满足绝对质量、覆盖、样本和时延要求后才可放行；不足时缩小声明范围或补样本。

## 6. 四角色完整验收与运行条件

R1 为声明范围的受控网页试点。没有通过审核的模块可以继续开发，但不能以“后续 App 再补”为理由从 R2 网页清单删除。R2 要求 P1-01～16 和 W1-01～07 全部具备与本轮范围匹配的验收证据。

- 学生在真实平板浏览器中完成账号登录、多页作业、提示、订正、求助、历史和各学习模块；共享设备换人及中断恢复均正确。
- 老师完成复核、识别修订、改判、知识点与记忆核实、题库审核、报告发布/更正/分享；无需开发人员代替正常日常操作。
- 管理员可在授权范围维护账号、档案、校区与运行信息；初始化根管理员仍沿用受控部署流程。
- 家长通过手机网页查看发布内容及更正；过期和已撤销链接失效。发布、复制和链接打开都不单独证明消息已送达指定家长。
- 错误证据被撤销后，当前判断、图谱、记忆和受影响报告同步更正；原作答和历次订正可追溯。
- 部署环境有真实身份、私有图片、持久数据库与 Worker；备份恢复、删除重放和回滚有业务级演练。
- 首发内容、设备浏览器、质量阈值、恢复目标、排班容量和验收负责人已冻结；真实使用期间的阻断缺陷关闭。

每日记录复核、答疑、异常处理和家长反馈工时。当前全量老师确认下，复核分钟 = 提交题数 × 平均复核秒数 ÷ 60，另加答疑和沟通；按集中提交时段检查峰值。记录每次成功、失败和重试的模型用量并核对账单，再评估每份作业和每生每日成本。

额外活动默认 0；学校任务完成、孩子愿意且有余力后才开放系统选做。学校布置的原有预习和原题纠错不受额外活动门禁阻断。参加、跳过或退出不会制造补做欠账，也不直接变成独立掌握证据。

## 7. App 迁移约束

- 账号和 `student_id` 连续；安装、升级、换设备不创建替代学员。
- 业务规则、模型调用、图谱、记忆与报告继续在同一后端；客户端使用相同有效版本和授权范围。
- 原图、题目、作答、订正父链及报告历史不因客户端迁移而复制或重建。
- 原生相机、文件管理、离线缓存、后台续跑、系统通知、签名与升级逐项验收；界面代码复用程度由后续客户端方案确定。
- 现有 Android 工程与历史测试可作为迁移基础，网页验收记录与 App 设备验收分别保存。
