# 跳过不可能产生可消费配对的语义对齐请求

状态：已整合并完成正式树定向回归，本机激活另行记录；未调用外部模型。此项减少无效调度，不改变识读协议或判题规则。

## 依据与边界

现有 `evaluate_alignment` 只允许必要印刷条件没有实质冲突的 `same_conditions` 提议成为可消费的 `pairs`。其必要条件是 `_printed_literals` 与 `_options` 相等；这只是排除条件，不能证明同题或判题正确。`reading_disagreement` 和拆分提议目前仅保留审计，不驱动来源合并或后续识读调度。

缓存 P02/P19 的先行离线证明分别检查了 20/196 条跨路候选边：每条边均被现有材料条件排除，最乐观单边提议也没有可消费配对。逐边计算避免了批量伪造提议触发 `source_reused` 的假阴性。此记录不能代表新模型请求的准确率或端到端时延。

## 最小改动

- `material_condition_signature` 只复用现有印刷 literal 与完整选项规范化。`material_conditions_compatible` 同时供调度预检和原配对验证器使用，避免两套规则漂移。
- `alignment_dispatch` 在原本会请求语义对齐的位置检查完整两路未配对来源。仅当所有跨路候选边都被既有材料条件排除，才返回 `not_dispatched / no_eligible_printed_edge`。
- 任意一条兼容边存在，都照常发送全部原始输入；不筛行、不改 source ID、不缩小唯一引用检查范围。相同印刷内容、未知题号、多空、不同作答或中文措辞不产生新拒绝规则。
- 每行只预计算一次 signature。80×80 场景是 160 次每行处理和 6,400 次简单签名比较，没有按边反复执行正则。
- 非法形状、重复 source ID、哈希或预检异常均回到原有请求和验证路径，审计标明 `eligibility_check_unavailable`；不能把不可计算冒称全边排除。空侧继续原有不派发行为。

## 审计与费用

独立 `multimodel_audit.alignment_dispatches` 保存协议版本、页面 asset ID、调度决定/原因、完整未配对来源集合 SHA-256、两路数量、候选/兼容/排除边数量。不保存额外题干、答案或模型内容。

跳过时不会创建 provider call、Attempt、usage、空成功响应或伪造的 provisional 结果。原始两路观察、题目、待核原因及其他模型请求保持原路径；有真实请求的阶段才进入原 calls 和计费记录。仓库默认关闭的逐项隔离与结构导航开关不受此改动影响，partial 页仍不进入对齐。

## 验证与后续门槛

新增回归涵盖全边冲突、存在兼容边的完整原输入、唯一引用不能因筛行而改变、同一必要条件 helper、空签名/选项顺序/终端等号/指数、多空 question、16 边中的两条实际可消费配对、80×80 单算签名、非法形状/重复源/哈希失败回退、独立零派发审计及用量记录。既有 semantic、two-model、partial-output、R1、question 和导航回归同时运行，记录在隔离候选的 regression 日志与文件清单。

离线相关回归 **730 passed**，仅有既有 Starlette/AnyIO 弃用警告。独立审查另完成 320 组 baseline/candidate 验证器差分，468 条可消费配对全部保留；预检跳过的 80 组均没有可消费配对。80×80 独立计数确认 source hash 与 signature 各处理 160 次。审计、非法形状及多页用量探针均通过。

独立审查使用缓存 P02/P19 做完整 pipeline 前后适配回放，业务输出、待核原因、其他调用审计与请求载荷（包括图像哈希）相等，每页少一次对齐请求。另按完整原始归档 ledger 核对，被移除的请求用量分别是 6,825 / 8,549 token。这不是新请求的实际节省或耗时测量。

缓存回放有明确边界：原始 alignment HTTP 正文不可用，使用验证后的 alignment 适配器；review 使用历史逐项结果按当前批次重组，review/visual metadata 是合成夹具；P02 缓存缺少当前流程需要的四个视觉目标。所有回放请求均来自缓存或 FakeClient，不能宣称修复这两页、识图更准或端到端提速。整合前核对基线与补丁哈希，仍不重复旧付费测试。
