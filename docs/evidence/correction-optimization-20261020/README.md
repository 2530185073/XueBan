# 减少误待核与整页等待时间

日期：2026-10-20。用户反馈上轮原图 19 项中有 8 项待核、约 89 秒。本轮针对同一张原图调整，不以降低待核数替代识图质量验证。照片、账号、密钥、模型原始响应及数据库保留在本机私有 runtime，不纳入 Git。

> 历史证据：下述“每页最多一次”及先前并行路径仅描述 2026-10-20 当时实现。当前 v5.2 已分批、按依赖核读；不能据此估算当前总调用量。现行预算边界见 [商用验收口径](../../COMMERCIAL_ACCEPTANCE.md)。

## 实现

- DeepSeek 与第二路模型并行、独立读取整张原图和学生作答；比较之前不交换候选。
- 分歧先由 AI 批量对照原图复核，每页最多一次，只处理存在分歧的目标，多页可并行。格式、单位排版、题干转述或不影响结论的差异可以消解；成功保存 `reviewed` AI 候选。涉及实际笔迹分歧时，另由 Astra 只看原图和目标题号独立核读，与复核并行；它看不到候选和参考答案，不判题。仍有不清或与所选作答不一致，则保留待核。
- 涉及实际笔迹时必须依据图像，学生作答只能取已归档候选原文，不生成第三种学生答案。判断“答案应该是多少”不能当作读到了该笔迹。当前有效作答清楚的涂改不用恢复其已废弃的书写历史。
- 编号漂移仅在完整题干与选项双向唯一、子题/空位相同时自动对齐，不按答案相同或数组顺序合题；原始编号留在私有审计。分数归一只处理明确排版，不求值、不改变分母、指数或带分数范围。
- 原始双读、分歧、复核结果和采用依据保留私有审计。复核看过候选，不计第三次独立赞成票。待核不会形成学生薄弱点，复核通过也不会变成老师确认。
- 学生端区分视觉不清、模型仍未确认、服务未完成；真实活动任务优先显示处理中。没有新添逐题付费重试，也不会自动创建老师求助。
- 运行配置明确选择模型 ID、`chat/responses` 协议和思考模式。当前本机选择 DeepSeek 快速初判 + GLM 独立判题 + DeepSeek 分歧复核；Astra Responses 只处理实际笔迹分歧的独立核读。

## 接口探针与选择依据

以下均是开发图上的单次观察，不是 p50/p95、质量排行或受控性能基准。网关负载会变化，提示在开发中也有版本变化。

| 请求 | 时间 | 观察 |
| --- | ---: | --- |
| 上轮 DeepSeek 完整双读中的第一路 | 75.0 秒 | 12,210 输出 tokens 中 9,496 为 reasoning |
| 本轮 DeepSeek 完整输出、关闭思考请求 | 19.9 秒 | 输出 19 项；项数本身不证明无漏项，仍不能独自确认涂改过程 |
| Astra 精简输出、low | 89.8 秒 | 19 项，但丢失涂改处疑点；未采用 |
| Astra 精简输出、medium | 94.8 秒 | 19 项，同样未保留涂改疑点；未采用 |
| Sol 完整输出、low | 79.0 秒 | 19 项，保留涂改疑点；本次未获得明显速度收益 |
| GLM 完整输出、关闭思考请求 | 38.4 秒 | 19 项，保留部分疑点；返回仍报告 reasoning 用量 |
| DeepSeek 复核上轮缓存的 8 个分歧 | 11.0 秒 | 消解 6 个非实质差异，保留手写分数与涂改过程两处疑点 |

最后一行只有复核是新请求，双读使用旧缓存，不是完整上传耗时。早期 GLM 复核试验约 41.3 秒，曾以最终结果推断涂改处中间数；发现后增加直接图像依据分类、禁止推算补字的提示和回归。不能拿早期错误放行的低待核数当成果。

尝试缩短输出参考了 [OpenAI 延迟优化说明](https://developers.openai.com/api/docs/guides/latency-optimization)；思考参数按 [推理模型说明](https://developers.openai.com/api/docs/guides/reasoning) 核对。本项目网关实测没有证明精简输出更快，因此保留完整题干、作答和判题字段。

52 秒试验后，链路增加仅针对实际笔迹分歧的独立只读，与批量复核并行；普通格式分歧不需要这一调用。70 秒原图中的分数排版误差与 66 秒修改图中的编号漂移是两处不同问题，分别记录修复和复验，不能用减少待核数掩盖重复条目。

首次合成新照片订正试验的初始 GLM 响应出现额外字段，按结构校验保留待核；新照片为正确。此轮只证明服务降级和版本隔离，不算错答识别闭环通过。

## 范围与限制

本轮最后修改图已实证：两初读会共同补出不可读的步骤，且一致时无法触发选择性盲读。需要独立于“两路是否冲突”的质量检查或更可靠的读取模型，再用冻结样本评估；不继续靠重复同一图片挑选更好的单次输出。

同一张图反复开发不能估计识别准确率。两模型仍可能共同误读，例如手写字母的歧义；当前 coverage 不宣称无漏题。既有历史候选保留原版本，新配置用于新上传，不在数据库里批量改写旧待核结果。正式上线仍需未参与调参的人工金标手写集、真实平板与托管点验收。
