# 隔离备份恢复验收 · 2026-10-21

本次证明新恢复工具能在本机创建、校验和清理专用副本，并正确重放备份之后新增的删除清单。没有切换真实服务，也没有重启 API/Worker、覆盖原库、删除真实原图或调用模型。

## 真实执行

- 从正在运行的本机数据库做事务一致的 PG 快照，恢复到唯一 QA 数据库；将其中 57 张已上传原图复制到 QA 私有目录，并逐张验证原文件 SHA。这是演练源副本，不把在线数据库+文件复制称为正式一致性备份。
- 在无其他写入者的 QA 环境调用正式 `backup`：42 张业务表，57 张原图，8,978,666 bytes，迁移 `0014_student_variants`。完整备份耗时 2.602 秒。
- 正式 `restore` 新建第二个数据库和新资产目录；各表记录数、迁移版本、原图元数据、SHA/字节数均一致。
- 备份之后，仅向 QA 独立清单追加一名合成验收学生的删除项。恢复时读取当前 QA 清单，清理该学生的 2 份作业、3 张原图、密码账号、学习证据，并停用其学生锚点。剩余 54 张原图、8,902,826 bytes 再次通过数据库关联和 SHA 校验。
- 恢复及首次校验耗时 3.226 秒；随后执行 `revalidate --writers-quiesced`，重复重放幂等，仍无自动切换。
- QA 源库仍保留删除前数据；57 张原始在线资产的哈希全部未变。所有 QA/恢复数据库、复制资产和 QA 运行密钥配置已清理，仅私有备份与审计证据保留。

以上耗时只适用于本次本机数据量，不代表生产 RTO 或大规模数据性能。

## 真实失败回收

另复制一份归档，故意放入 `../escape` tar 成员，并重新计算外层归档 SHA，验证“校验和正确”不会绕过安全展开规则。恢复在新副本中拒绝该内容，删除了仅本命令创建的数据库与资产目录，未写出逃逸文件，原数据不变。

早期演练还发现 PostgreSQL 的 OID 在 JSON 对象中被编码为字符串，与直接标量读取的数字不同，导致所有权检查保守拒绝清理。已显式转为 bigint，保留失败记录并重新执行完整演练通过；没有放松身份检查。

## 清单历史边界

本轮只读盘点时，原 Mac runtime 没有配置删除清单；数据库中删除请求和无请求的已删除学生均为 0。演练在 QA 环境显式建立独立空基线并追加测试删除，不能因此声称过去的真实备份已满足删除重放要求。新 `mac_local init` 已建立私有清单；既有 runtime 的激活由主任务明确盘点、绑定及重启，本文不代替该步骤。

生产异地取回、密钥恢复、维护窗口、人工切换及现场连续使用仍需独立验收，P1-14/P1-16 不应仅据本记录整体关闭。
