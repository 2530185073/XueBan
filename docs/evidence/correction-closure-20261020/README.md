# 双模型纠错与订正闭环验证

日期：2026-10-20。范围：整合 PR #4 与当时的 `main`（`4e71371`），在独立工作树实现、回归并启动本地网页。账号、照片、原始模型响应、数据库和密钥均保留在本机私有 runtime，不纳入 Git。

## 本轮行为

- 每张原图由 DeepSeek 与 Astra 分别完整识读和判题，两路不互相读取候选内容。按题号/空位及完整题干匹配，比较可见作答和判定；不做多数投票，不凭单方成功放行正确。
- 一次整页任务保存所有候选及审计，没有给已有 assessment 的每道题再发付费检查。服务未完成、笔迹歧义和数学分歧均保持待核，并分别说明原因。
- 新照片订正与原题、父作答和照片版本绑定。旧作答的错误证据保留；识读修订、撤回等失效原因不能冒充历史学习事实。
- 学生题卡恢复订正、提示、求助、历史和原图联动；数学开头的数字、小数和指数不再被误作题号删除。
- 知识图谱和家长报告区分 AI 初判与老师核实。新照片 AI 判对会在日报保留“已提交订正，AI 初判正确（待老师核实）”，不增加老师确认统计。
- 基本原图纠错不要求先补齐年级和教材；知识归档继续要求教材与已审核图谱范围匹配。

## 真实 API 与持久化

使用独立 QA 学员账号，通过正常 HTTP 登录、上传、任务轮询和读取接口验证，不直接写入模拟判题结果。

1. **合成单题闭环通过**：`3(x−2)`，原答 `3x−2` 被判 `incorrect`，新照片 `3x−6` 被判 `correct`。分别约 16 秒和 10 秒；两次都是双模型独立核对一致的 AI 候选。父作答关联、两张照片隔离、输入版本和旧判定失效均验证通过，未伪装为老师确认。
2. **手写开发图首次试验**：两接口均成功，约 80 秒，但 19 个作答项因中英文空格、题尾空括号等差异全部待核。修正受限的排版归一化后，离线重放同一对原始输出为 13 项正确、2 项未作答、4 项待核。仍保留选项字母/符号、模糊笔迹和涂改步骤分歧；此结果是离线重放，不是新的联网成功。
3. **118 秒预算的故障实测**：在手写开发图和用户原图上各出现一次 DeepSeek 超时，Astra 分别约 86 秒和 85 秒返回。两次都持久保存 19 项待核，无额外逐题检查；失败没有计入错题或薄弱点。未确定的供应商用量仍标为未知。
4. 因上述连续触及截止时间，将 DeepSeek 单请求总预算调整为 200 秒，Astra 保持 118 秒；两方仍各请求一次。最终用户原图通过 HTTP 整页联调，约 **89 秒**保存 **19 项：11 项 `correct`、8 项待核**。DeepSeek 约 75 秒、Astra 约 87 秒，说明上游延迟存在波动，不能把这次成功归因于延长预算。原作答、候选判断、逐题来源和两个实际请求的审计均已持久保存，仍只有一个整页任务。

最后 8 项待核中，选择题有字母/符号及单位排版差异，连续偶数题和代入求值题有两模型转述范围不同，另有手写分数、涂改过程的识读/判断分歧。保守门禁降低了确定结果的覆盖范围；这些待核项不等于学生答错。仅凭这张图不能得出准确率，更不能证明两模型一致的项全部正确。

## 浏览器验收

在本机实际加载的学生网页验证：

- 刷新恢复最新作业；退出再登录仍可看到原答 `3x−2`、订正 `3x−6` 及当前/历史判定。
- 从订正图翻回原图，再点击同一题卡，可以重新定位到该题当前订正照片。
- 相册订正入口实际打开单文件选择框，取消后没有上传或新增模型调用。
- 修复切换草稿时旧轮询吞掉新轮询、显式重查被旧请求吞掉的问题，并补自动化回归。

浏览器验收使用隔离 QA 账号，结束后已退出；没有向家长发送内容。

## 仍未验收

本轮说明代码约束、真实接口、持久化和浏览器闭环，不提供识别准确率。手写开发图、用户原图和合成单题都不是冻结保留集。双模型可能同样误读、漏题或判错；原图逐字转录和数学判断仍需人工金标评测。

整页服务稳定性、平板拍照/弱网/进程恢复、跨学科覆盖及正式托管点流程尚未商用验收。教材目录不等于逐知识点教研审核。跨日订正目前更新原作业日期的日报，尚未单列“今天订正旧作业”栏目。保留歧义的旧观察通过新照片或确认修订恢复，不会因点击重试自动删掉原疑点。
