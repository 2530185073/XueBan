# 整页多模型纠错联调（2026-10-18）

本轮交付对象为本机学生网页，不是新的 Android 安装包。原账号、数据库、照片和订正父链保留。测试使用独立学员，未替换真实学员身份，也未向家长发送内容。

## 实现

- DeepSeek 整页批改与 Kimi 整页只读并行，各自只看原图；疑难题按页交给 Astra 独立复核。模型看到其他模型答案之前已完成自己的读图，不采用简单多数投票覆盖字迹疑点。
- 整页持久任务同时保存题目、原作答、CheckRun 和模型候选判断；网页直接读取结果，不再对已有判断的每题串行请求 `/checks`。
- 明确标注实质分歧；待核题不触发解题提示，也不挡住其他题继续做。识读一致不等于两个模型都验算过，更不等于老师确认或知识点掌握。
- 订正仍要求新照片与原题完整对应；匹配允许题号和明确排版差异，不允许数学内容变化、缺条件或把旧答案用作新答案。同干多个空仍按子题号区分。
- 每次调用均有真正的总超时，Responses 必须收到完整完成事件；失败不自动重复付费。账号/API/网页构建不接收模型密钥。

## 本轮发现并修复

1. 原 8192-token 上限被主模型推理占用，整页 JSON 被截断。多模型路径按阶段提高输出预算，旧单模型默认上限保持不变。
2. 主判把题号写进题干、另一模型省略题号，导致大量一致答案被误拦。只移除与题号字段相符的装饰；保留公式括号、数值、负号、指数及省略号。
3. 上标与纯排版空格造成误拦。限定归一支持 `a²`/`a^2`、`4 a`/`4a`，保持 `x²`/`x2`、`1 2`/`12` 等区别；原始文字仍原样归档。
4. 随机案例 ID 让整页题目乱序。网页按题目创建顺序排列并保留微秒，重新切分的题留在原题位置。
5. 失败后重试成功，刷新仍可能误选 UUID 排序中的旧失败任务。恢复显式按创建时间选择最新整页任务，保留未知写入的幂等重放；不会为成功结果重复提交检查。

## 已执行验证

- 后端 SQLite + PostgreSQL 全套：784 passed、5 skipped；后续归一/绑定改动再跑相关双库及提供方测试：402 passed、2 skipped。跳过项为 SQLite 分支的 PostgreSQL 专项，对应 PostgreSQL 分支实际执行。
- 学生网页：18 个文件、175 项测试通过；契约生成一致性、TypeScript 和 Vite 构建通过。现有单包大于 500 kB 的构建提示仍在。
- 一期契约：4 个 Schema、328 个引用、32 个 API 操作、49 个合成样例及 19 个负例通过。
- 真实合成错题闭环：`3(x-2)` 的 `3x-2` 判错，提交新照片 `3x-6` 后判对；原/新作答、照片、父链及判断输入版本分别保存，两次结果均为模型候选。初次任务约 20 秒，新订正约 12 秒；小样例耗时不代表整页耗时。
- 最终代码重启后再次联网复验同一合成闭环：原作答判错、新照片判对，任务分别约 12 秒和 16 秒；输入版本、订正父链及独立资产检查通过。
- 整页联调中，三路调用真实成功过；刷新后继续使用同一服务端任务，没有追加逐题 `/checks`，待核题的“先看其他题”有效，观察阶段无页面脚本异常。
- 对一份保存的三路输出做离线回放，修正前 20 项中 2 项通过识读归并，修正后 13 项通过；`12x`/`2a+10`、u/v 字迹疑点仍保留。该数字是同一次输出的归并对照，不是新调用结果或纠错准确率。

真实作业照片、模型原始候选、账号和接口凭据只留在仓库外私有运行目录；本目录不包含学生图片或真实账号口令。

## 最终整页复测

使用新分项提示与比较规则，在真实网页重新上传同一张经过改动的手写页，服务端完成一次整页任务，生成 **19 个作答项**，没有再把第 5 题两个表达式合成一项。实际为 5 项初判正确、2 项未作答、12 项待核；界面的“需订正 2”在此对应两个未作答空格，不是已经确认的两道错题。

两路初读分别约 90.3 秒、91.1 秒成功返回，Astra 复核达到 118 秒总时限，整个推理阶段约 209 秒。复核失败保留为明确待核，没有变成互证通过，也没有把未知调用费用记为零。此前一次三路均成功的整页任务约 132 秒；接口耗时和可用性存在波动。

刷新后仍是 19 项、原题顺序正常，不出现错误的“继续未完成”提示；浏览器观察到逐题 `/checks` 请求为零。“先看其他题”可切换，候选及待核均保留原照片和独立作答记录，未修改其他学员数据。

**当前多模型归并仍偏保守。** 这次整页可操作流程通过，不等于识图质量已经达标；模型读回的题干范围、真实字迹疑点及第三方接口超时仍会造成较多待核。应继续用多张不同作业建立质量集，分别衡量误判、漏题、待核率和耗时，再决定正式试点路由。

## 边界

这是一张经人工改动的手写样例及一题合成闭环的开发联调，不代表初中各科、所有手写类型或现场准确率验收。模型仍可能读错题干或作答；有疑点时显示待核，不形成已确认薄弱点。公网部署、平板真机拍照及正式托管点试点不由本次验证替代。
