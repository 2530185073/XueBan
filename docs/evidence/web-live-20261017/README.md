# 学生网页真实联网联调 · 2026-10-17

入口为 Mac 本机 `http://127.0.0.1:8000/learn/`，使用生产构建的 React 网页、同源 FastAPI、PostgreSQL 17 和已有标准模型 Worker。此记录只证明合成场景下集成可运行，不代表中文手写准确率或现场验收。

## 浏览器实际操作

- 短期配对链接兑换会话；页面立即清除 fragment，显示已授权的合成学生。
- 选择自制印刷图片 `evals/correction/fixtures/ark-smoke/original.png`，点击开始检查。模型读出 `Expand 3(x - 2)` 和错误答案 `3x - 2`，网页显示需要订正。
- 点击“给我一点方向”，真实模型提示为“请检查括号内的每一项是否都参与了运算。”；展示事件已持久化。
- 点击“我已在纸上订正，拍新作答”，选择 `corrected.png`，开始再检。新答案 `3x - 6` 显示“初判正确”，不是老师确认。
- PostgreSQL 只读核实：同一作业保留两个 attempt、两个不同图片资产；新 attempt 的 parent/root 正确关联原 attempt；两次均保留 `hint_used`。原提示随原判定失效为 stale；未将提示后答对记成独立掌握。
- 刷新浏览器、打开历史并恢复当前结果；读取同一账号已有 Android 作业记录。另一个独立合成作业验证坐班求助返回并入库为 waiting，未声称老师已处理。
- 1440、1024、390 像素宽度均无页面横向溢出；1440与390截图人工查看。文件选择实际验证；平板实机相机尚未验证。

## 核心链路实际请求

[脱敏数据库证据](result.redacted.json)记录同一作业的五个任务：初次识别、初次检查、方向提示、新订正识别、再检查。五项均 succeeded、各执行一次，返回 `deepseek-v4-1-flash-260910`，有真实请求ID与用量。该JSON只包含自制合成题及非凭据元数据。

浏览器操作调试中还创建了一份独立正确作答作业（另两次模型任务），不计入上述五步链路或准确率。未把任何运行失败、重复手工操作隐藏成严格性能评测。

## 本次修复与限制

真实浏览器发现并修复默认 fetch 的接收者错误；预编译 Schema 校验器兼容禁止 unsafe-eval 的 CSP。另由独立代码审查和模拟回归覆盖未知写入原幂等键恢复、身份通知循环、历史草稿复用、订正换图上下文及终止失败后的明确重试。

模型框仍可能偏移；框标注为 AI 推测。真实手写整页质量问题沿用 [Mac实测记录](../mac-live-20261017/README.md)，并未被网页移植解决。历史页面当前查看最新题目状态，逐版本证据浏览尚未做成时间线。这里只交付本地联网开发版。
