# 一期生产契约初稿

状态：`draft-0.1`。本目录只定义待实现的生产契约，不表示真实服务、账号、OCR、判题或 App 已完成，也不与 `prototype/` 的演示路由兼容。集成负责人审核后才能冻结。

首发背景为**初中、人教版、安卓平板**。具体年级、册次、教材版次、首批科目和可判断题型仍需明确；契约允许保存未知信息，不以教材目录、题库 ID 或知识点映射作为纠错前提。

## 最小完整边界

本稿覆盖身份上下文读取、作业/私有上传、真实识别任务、题目与答案识别修订、检查、提示及实际展示、订正、求助与复核、历史和删除。后续图谱、长期记忆、练习与报告没有接口。认证签发/刷新接项目选定的真实身份服务，不在本稿虚构账号实现。

| 文件 | 用途 |
|---|---|
| `openapi.json` | OpenAPI 3.1 接口边界、权限、请求与响应引用 |
| `states.schema.json` | 相互独立的执行、判断、结果和订正状态 |
| `data.schema.json` | 持久业务对象及只读资源 |
| `requests.schema.json` | 客户端允许提交的字段；不接受自报租户/身份/确认来源 |
| `events.schema.json` | 事务 Outbox 事件；只含引用和版本，不复制原图或作答正文 |
| `examples.json` | 合成样例与跨题目版本订正链，无真实学生/作业资料 |
| `validate.py` | 离线 Schema、引用、接口结构、样例与关键反例检查 |

## 主流程

1. `GET /v1/me` 取得服务端确定的可访问学生；创建该学生的作业。
2. 创建上传凭据，向私有对象存储上传；完成确认验证哈希/大小后才可提交识别任务。票据过期时读取原图片状态并对同一 `asset_id` 续签，不重建照片或作答；新一次续签用新幂等键，同次续签的网络重试沿用该键。任务结果引用作业；读取作业得到题目和纠错记录 ID。
3. 识别任务在服务端创建采集题目、原作答和纠错记录。读取题目/作答并按需修订；漏题、错切通过受权 `layout-revisions` 补题/拆合。旧题及记录保留且标为 `superseded`，新题取得新身份与原作答，保留替代关联。有明确输入版本后创建检查任务。
4. 读取任务、检查和当前纠错记录。请求分层提示；客户端实际展示后才提交展示回执，不把请求提示当成孩子已看过。
5. 在同一作业下上传修改图，创建新订正作答；服务端创建新识别任务，识别成功后再创建检查任务。点击完成不能改变判定。
6. 老师通过求助队列接单，读取原图及版本，确认、改判或保留未解决。模型技术失败尚未产生判断时，受权老师可用 `manual_initial` 直接核实：引用真实题目/作答版本，生成 `origin=staff`、`check_id=null` 的决定，明确计为人工结果。有有效判断时必须走确认/改判。无把握时仍待核实；历史读取最新有效记录，也能追溯旧版本。

## 必须由实现保证的约束

- 所有 API 使用真实 bearer 身份与服务端授权；学生路径只是资源选择，不是授权凭据。服务端核验租户、托管点、学生、角色及有效授权。禁止 `X-Demo-Actor`、模型自报身份或任意客户端 `student_id` 写入。
- 学生切换必须由已授权的设备/工作人员流程完成。原图读取重新鉴权并签发短期 URL；上传票据不赋予业务记录读取权限。请求中的资源 ID 均要逐项校验归属。
- 每个写操作带 `Idempotency-Key`。作用域为认证主体、授权学生、HTTP 方法和路由；同键同载荷返回原受理/业务结果，不重复执行，同键不同载荷返回 `409`。幂等记录保留时间至少覆盖客户端重试窗口，具体时长在部署配置冻结。
- `expected_revision` 表示被变更聚合的当前版本：作业、图片、题目、作答、纠错记录、求助或提示分别比较自己的版本。图片完成确认与识别提交比较图片/作业版本；请求明确引用的题目、作答识别和判断版本也须匹配。旧版本返回 `409`，不得静默覆盖。
- 原图不可覆盖；题目/答案识别修订生成新版本。每次真实订正生成新作答；相同图像哈希只能辅助上传去重。父子作答必须属于同一学生及同一采集题目，可引用不同题目 revision；题干修订后重新核验关联，不强制旧父作答改写为新版本。
- 切题合并/拆分须产生新的采集题目身份。`layout-revisions` 对作业和受影响题目逐项比较版本，事务内使旧判断失效、旧题/纠错记录变为 `superseded`；异步生成新题、原作答及替代关联。补漏时受影响旧题列表可空。旧订正照片与历史不删除，新题建立新根链，不能把旧题订正强挂给另一题。`parent_attempt_id` 必须存在且不成环；根作答由服务端计算。
- 原作答可在同一题目修订后的新版本下重检；检查同时保留作答原始版本和实际核验的题目版本。`case_revision_at_submission` 只记录受理时的 CAS 审计值，任务创建、求助、展示提示、暂停造成的聚合 revision 增长不使内容检查失效。Worker 校验实际题干、答案识别与图片输入版本及有效性；内容已过期则结束为 `superseded`。当前作答指针已变化时结果只能留作对应旧作答历史，不能覆盖新作答当前状态。
- 模型/规则输出仅为候选。`confirmed` 当前仅接受受权老师的新决定；本稿没有自动确认入口。模型置信度或模型意见一致均不能触发确认。后续开放特定题型自动确认必须另审契约、来源与验收规则。
- 每次改判创建新决定；原决定标记撤销/过期并保留替代关系。判断变化与当前指针、提示失效、Outbox 事件同事务提交。已展示的提示保留真实历史，新请求不可使用失效来源。撤销原判断不得删除后来真实订正。
- 初始正确与订正正确均要核实才能成为 `verified_resolved`。暂停/恢复 API 不接受“完成”指令；提示后改对不代表独立掌握。
- `schema` 能验证形状与局部状态约束，不能替代数据库外键、事务、权限、跨资源版本/循环检查或真实判题评测。这些是服务集成测试和运行验收项。

## 三类失败边界

| 边界 | 表达方式 | 客户端行为 |
|---|---|---|
| 业务无法判断 | 检查任务成功；判断为 `unable_to_judge`、`needs_review`，给出原因 | 显示待核实/补拍/求助，不当作错题，也不重试到“答对”为止 |
| 请求被拒绝/冲突 | `401/403/404/409/422`，统一 Problem；旧版本和幂等冲突为 `409` | 重新鉴权或刷新当前资源并由用户确认；不能盲目覆写 |
| 执行/服务故障 | 受理前 `503`；受理后 Job 的 `retryable_failed/failed` 与结构化错误 | 按任务状态及退避续查/重试；不得写正确、错误或“已确认” |

检查任务成功只表示生成了结果。上传成功、识别成功、检查成功、已确认正确和订正解决是不同事实。请求超时后用相同幂等键恢复；禁止换键重复创建作答。

## 事件、删除和读取

Outbox 事件与源记录提交同事务，至少一次投递；消费者按 `event_id` 去重、按聚合版本处理乱序，并能读取源记录当前有效版本。事件不是任意客户端写入口。没有后续消费者也应能提交纠错记录。源记录删除后事件不再暴露其正文。

历史和列表使用游标及限制数量；所有结果再次校验授权，图片仅在鉴权后临时读取。删除由治理权限发起；请求受理后阻止新增处理并使在线读取失效。删除状态包括原图、派生文件、结构化敏感记录、设备缓存和备份删除清单；离线设备未确认清理前不虚报全部完成。备份恢复必须重放删除清单。普通坐班答疑权限不能执行删除。

## 本地验证

```sh
python3 -m pip install -r contracts/phase1/requirements.txt
python3 contracts/phase1/validate.py
```

需要 Python 3.11+；已在 Python 3.14.3 与 `jsonschema==4.26.0` 验证，依赖见 `requirements.txt`。安装依赖可能联网，验证过程不联网加载任何 Schema。脚本检查 Draft 2020-12、全部本地引用、OpenAPI 操作/参数/鉴权/幂等结构、合成样例，以及模型不能确认、Job 失败不能带成功结果、版本必填等反例。它是本目录的契约检查，不是完整 OpenAPI 元 Schema 验证器，更不代表接口已实现。CI 集成与正式 OpenAPI 工具校验由集成负责人接入。
