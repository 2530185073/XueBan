# 坐班 Web 工作台

React + TypeScript + Vite 的一期工作台初稿，服务**托管现场的作业求助、原图核实、订正与帮助记录**。默认没有连接或学生数据。当前后端本轮仅实现身份与作业基础路由，求助、接单、题目读取和复核 API 尚未接通；前端不会把失败请求显示成完成。

## 启动

需要 Node.js 22.12+；本轮使用 22.22.0。依赖和 lockfile 已固定。

```sh
cd apps/staff-web
npm ci
npm run dev       # http://127.0.0.1:5173
npm test
npm run build
npm run preview   # http://127.0.0.1:4173
```

开发与预览均仅绑定本机，端口占用会失败，不偷偷换端口。后端 CORS 必须精确包含浏览器实际 origin；`http://127.0.0.1:5173` 和 `http://localhost:5173` 是不同 origin，不能混用。HTTPS 正式服务地址可在连接窗口填写；本机联调仅允许 localhost / 127.0.0.1 / ::1 使用 HTTP。

## 已实现与界面状态

- 左侧待办和求助队列、筛选、内容搜索与游标加载；中央原图和题区定位；右侧候选判断、每次作答、实际提示展示记录及复核表单。
- 宽屏三栏，窄屏顺序布局；原图可展开、切换图片和显示题区。当前像素定位直接使用契约的 `original_pixels`，设备 EXIF 方向及服务端规范化坐标还需真实图片联调验证。
- 初始页面是未连接态。连接时先调用 `GET /v1/me`，身份必须具备坐班或校区管理角色；没有可访问队列时显示实际空状态或错误。
- 访问令牌仅在内存中用于 `Authorization: Bearer` 请求头，不写 localStorage、sessionStorage、URL、日志或文件。断开或 401 会清空身份、学生资料、队列和原图。**当前令牌输入只是研发联调入口，正式员工登录、SSO/刷新与授权交接尚待整合。**
- 每次服务成功响应都按共享 JSON Schema 验证；200 但形状错误同样不显示成功。
- 接手、复核和结束帮助只有在服务端确认后才更新提示，再读取最新资源。没有接单成功不能开启复核；有效性、题干版本、当前作答和识别版本都参与前端防错，服务端仍是授权与并发控制的最终边界。
- 提示显示 `first_shown_at` 对应的真实展示状态，不能把提示生成当作孩子已经看过。帮助结束不等于题目答对。

右上角或中央的 **“合成样例预览”** 是独立只读模式：整页有醒目标注，人物、题目与原图均为合成；不创建 API client 或调用后台，不发送接单/复核/完成请求。样例图保存在 `public/sample-homework.svg`；其中的算式只为界面设计，不是模型输出或教材依据。退出预览清空样例。界面使用中文字体回退，并按可用网络加载 Google Fonts 的 Noto Serif SC；该请求不携带 API 令牌。

## API 映射

客户端严格使用 [一期契约](../../contracts/phase1/README.md)，没有沿用 prototype 的演示身份头。

| 页面动作 | 契约端点 |
|---|---|
| 核验工作人员身份 | `GET /v1/me` |
| 读取求助队列 | `GET /v1/help-requests?limit=30&cursor=...` |
| 读取纠错记录 | `GET /v1/cases/{case_id}` |
| 原题、各次作答、当前判断 | `GET /v1/questions/{question_id}`、`GET /v1/attempts/{attempt_id}`、`GET /v1/decisions/{decision_id}` |
| 帮助和提示历史 | 队列里的 `HelpRequest` + `GET /v1/hints/{hint_id}` |
| 获取短期原图地址 | `GET /v1/assets/{asset_id}/access` |
| 接手求助 | `POST /v1/help-requests/{help_id}/claim`，仅提交 `expected_revision` |
| 复核/改判/撤销/保留未决/人工初判 | `POST /v1/cases/{case_id}/reviews` |
| 结束现场帮助或记录未解决 | `POST /v1/help-requests/{help_id}/complete` |

当前共享契约**没有** `GET /v1/help-requests/{help_id}`；详情用队列对象与 case 等已有资源组合读取，不虚构单条求助接口。老师显示名未包含在当前身份契约中，界面不伪造；学生姓名仅通过 case 的服务端 scope 与授权学生列表关联。

`scripts/generate-contract-types.mjs` 从共享的状态、数据和请求 Schema 生成 TS 形状；`npm run contracts:check` 在构建时检查漂移。AJV 在运行时验证完整约束，包含 `allOf`。契约更新后执行 `npm run contracts:generate` 并复核测试；本目录不修改共享契约来迁就 UI。

## 错误与重试

| 状态 | 工作台行为 |
|---|---|
| 401 | 清空会话与已加载资料，要求重新授权 |
| 403 | 清除当前学生/队列详情，显示无权限，不降级演示身份 |
| 404 | 资源不可访问或接口未接通；不补假数据 |
| 409 | 版本或幂等冲突，提示刷新核实，不自动覆盖 |
| 422 | 阻止不合契约请求，显示需修正内容 |
| 503 / 网络错误 / 超时 | 不宣称完成；未确认写入保留原内容与原幂等键 |
| 成功响应不符 Schema | 视为响应错误，不把它当成成功 |

写入使用随机 `Idempotency-Key`。受理结果未知时锁定提交表单，显示**重试原操作**；该动作沿用原键和原载荷，不根据后来输入生成新请求。刷新队列不会清除此状态，不能用另一笔操作绕过。确定的拒绝会结束该待确认项，服务端版本冲突仍需刷新核实。

当前重试信息同样仅在内存中：关闭/刷新浏览器或断开会话后不能靠本页恢复未知写入。正式发布前须接服务端操作恢复查询及授权后的重试恢复机制；这是当前未完成项，不能将本工作台视为完整生产客户端。

## 验证与边界

本轮 `npm test` 验证 API 路径/载荷、401/403/409/503、未知写入同键同内容重试、非法身份字段、响应形状和合成数据契约；`npm run build` 执行契约漂移检查、TypeScript 检查与生产构建。根任务另行进行浏览器视觉检查。测试成功不代表真实老师/作业/后端全流程已联通。

仍待实现：员工正式登录、真实求助与复核后端联调、会话刷新、跨页面未决操作恢复、原图过期刷新策略、识别修订/切题修复 UI、完整多题/多页大数据量验证、现场可用性验收及生产部署的 CSP/审计。没有课程管理、排行榜、图谱或假统计。
