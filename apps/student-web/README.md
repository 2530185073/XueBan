# 学伴学生网页端 0.2.0

优先交付电脑、横屏平板和手机浏览器中的真实拍照纠错。温纸色与墨绿的作业本界面，核心是自己的学校作业：选图预览 → 明确开始检查 → 原图与逐题初判 → 分级提示 → 新照片订正 → 再检查。没有模型 Key 输入、模拟正确答案、排行榜或额外练习任务。

## 开发与构建

Node.js >= 22.12；React 19.3.1、TypeScript 5.9.3、Vite 8.3.4 与坐班 Web 保持一致，依赖使用 package-lock.json 锁定。

```sh
cd apps/student-web
npm ci
npm run dev
npm test
npm run build
npm run preview
```

开发入口 `http://127.0.0.1:5174/learn/`，`/v1` 代理到 `127.0.0.1:8000`；preview 为 4174。生产构建输出 `dist/`，base 固定 `/learn/`，由项目后端同源提供。`node_modules/`、`dist/`、`*.tsbuildinfo` 不提交。

**实际完整联调优先使用后端 `http://127.0.0.1:8000/learn/`。** 私有图片票据严格同源。若完整上传链路走 Vite 5174，后端 `PUBLIC_BASE_URL` 也必须配置为 `http://127.0.0.1:5174`，使图片 PUT/GET 通过同一代理；不能拿 8000 的票据在 5174 页面跨源上传。不绕过这个限制。

## 使用与数据边界

- 默认使用老师开通的长期账号和密码。学生账户固定绑定后端 `student_id`，没有任意学生 ID 输入或孩子切换入口。换设备、修改密码仍读取同一学生的服务端历史；本地草稿按服务端主体与学生隔离，不擅自合并旧身份的数据。知识图谱尚未实现，本轮不展示虚构图谱或掌握度。
- 登录走 `/v1/auth/login`；会话只写 sessionStorage（token、到期时间和账户会话标记），用户名、密码不写 sessionStorage、localStorage、IndexedDB 或日志。正常刷新先 `/v1/auth/account`，通过服务端认证后才读 `/v1/me` 和该学生草稿。旧配对会话/待交换码不再恢复；旧 `#pair` 片段只清除，不兑换。
- 初始密码必须更换，改密前不调用 `/v1/me` 或读取作业。普通用户也可在顶部“修改密码”操作。新密码按 Unicode 码点计 15–128 字符、UTF-8 不超过 512 字节，保留空格；表单使用 username/current-password/new-password autocomplete。登录/改密/退出均带幂等键，涉及密码的未确认请求只在内存保留原内容和键；刷新后可用新密码重新登录，绝不持久化密码换取自动重放。
- 退出真实调用 `/v1/auth/logout`，无论网络结果均清除本地会话、内存照片和身份。断网时明确提示服务端撤销未确认，不冒称服务端退出成功。已保存的 IndexedDB 草稿仍隔离保留，只有再次通过对应账户授权才可读取。
- 校区管理员从同一登录页进入“学员账号”管理页；允许管理员 `/v1/me` 不含学生授权，不为显示管理页创建假学生，也不调用学生作业接口。管理请求只走 `/v1/admin/`，与作业未知写日志分离。
- 首次选择照片仅创建本地预览，点击“开始检查”才提交模型任务。JPG/PNG 图片入口使用 HTML file input；“用相机拍一张”使用 `capture="environment"`，由手机/平板浏览器提供拍照能力，电脑优先选图。
- 逐题状态区分初判正确、需要订正、识别待核实、无法判断和老师确认；任务完成只代表有可查看结果。照片未读清、无题目、无有效判断均不展示“全部正确”。区域框标注为 AI 推测，不能视为精确错点定位。
- 左栏照片通过当前 Attempt 的 asset IDs 获取 Blob，不把 signed URL 放到 DOM。切换题目后展示对应作答图片；图片加载失败明确提示，不用旧照片替代新作答。Blob URL 在替换/卸载时释放。
- 学生端不直接展开可能含完整答案的 basis。提示由实际按钮请求，实际展示后记录 views；新订正默认报告 unknown，由后端继承真实帮助记录。求助只有服务端成功后才反馈已提交。
- 订正预览“换一张照片”保留 case 和父 Attempt，提交前父 Attempt 变化则要求刷新。完成后优先选中刚订正的题，而不是跳回整页第一题。
- 打开历史、刷新结果只读，不自动发起新的付费检查。“继续未完成的检查”是独立明确动作。已有草稿使用 core 返回的 draftId，不复制未知请求形成第二条任务链。

## 申诉、订正记录与历史（P1-10 / P1-11 / P1-13 学生端）

- **申请老师重查**：当前题有有效判断（AI 初判 candidate、待核实 needs_review、老师确认 confirmed）或已 verified_resolved 时，题目下方“求助与重查”可填写不超过 200 字的说明（可不填，会用默认说明），提交 `kind: appeal` 求助。写入与其他写操作一样先进 IndexedDB 操作日志：结果未知时用原 Idempotency-Key 和原说明重放；同一判断已有等待/处理中的重查时不重复创建；老师处理完（resolved/unresolved）或给出新判断后可再次申请。“请老师帮忙”“文字和照片不一样”同样走这条路径，并防止同类求助重复打开。提交后只重新读取，老师处理前当前结果不变。
- **求助状态**：逐个读取 case 的 `help_request_ids`（`GET /v1/help-requests/{id}`），显示 等待老师 / 老师处理中 / 老师已处理 / 老师暂未解决 / 已取消，以及老师的处理说明。
- **订正记录**：每题可展开的时间线按服务器时间排序，合并：原作答与第 N 次订正（缩略图经私有图片票据获取，标注 看过提示 / 老师帮助 / 看过答案、识别待核实、当前作答）、每次检查的判断（AI初判 / 规则检查 / 老师确认 / 老师改判，含结论和“针对第几次作答”）、实际看过的提示（层级、是否含答案）、求助与重查、老师复核（确认/改判/撤回/暂不判定及理由）。stale/retracted 一律显示“已失效”并划线；“当前结果”只在记录 `currently_effective` 为真、且等于 case 的 `current_decision` 时出现，刷新或读到旧快照都不会把失效结果重新当成当前结果。不展开判断 basis（可能含完整答案）。
- **老师重新切分**：layout repair 后被替换的 case（lifecycle superseded）不再出现在逐题列表，替换出的新 case 放在原位置（即使作业的 case_ids 尚未列出也会沿 `replacement_case_ids` 读到）；结果区显示“老师已重新切分此题”。对已替换题的订正/求助会提示刷新后在新题上继续；deletion_pending 的 case 也不显示。
- **历史页**：按创建日期分组（今天/昨天/具体日期），可按科目（`curriculum.subject` 为空显示“未标注科目”）和状态（有待订正 / 待老师核实 / 已完成）筛选；状态来自后台逐份读取的 case 统计，未统计完的作业不会被错误归类。顶部“继续订正”和卡片上的“继续订正”直接打开并选中第一道需要订正（其次待核实）的有效题。每份作业只显示“本次拍到 N 题：需订正 a，待核实 b，（AI初判正确 d，）已确认正确 c”，从不显示整份作业正确率；collection_scope 不是 declared_complete 时注明只统计本次拍到的题目。没有知识图谱、报告或练习的空入口。
- **本机缓存**：启动时清理超过 7 天未更新的草稿（含照片）和操作日志；结果未知的写入会让对应草稿继续保留，直到写入确认或自身满 7 天，届时丢弃并在该账号下次登录时提示一次。旧版本无时间戳的日志从第一次清理开始计时。`/v1/me` 或 `/v1/auth/account` 返回 403 access_denied，或本地会话未到期却收到服务端 401 authentication_required（会话被撤销、账号停用/删除）时，清除该账号与学生范围内的草稿、照片和日志并退出；仅本地会话过期不清除。退出登录会清空内存图片并撤销该范围创建的全部 blob URL。历史页底部“清除本机草稿”需二次确认，只删除本机数据，不影响服务器作业。
- **平板与无障碍**：以 1024×768 横屏为主，照片与结果左右并排、照片随滚动保持可见；390 宽单列无横向溢出。平板/触屏下最小字号 11px、主要控件不小于 44px；筛选按钮用 aria-pressed，当前题用 aria-current，状态更新用 role=status/aria-live，重查说明有可见标签和字数提示。新增样式在 `src/record.css`，没有新增内联脚本或样式。

## 工程分工与验证

`src/core/` 为契约、身份、IndexedDB、上传和模型任务适配（`cases.ts` 为 case 排序、替换与统计分类，`store.ts` 含 7 天清理与按范围清除）；`useStudentWorkspace.ts` 为 UI 状态协调；`presentation.ts` 为展示和订正上下文规则；`timeline.ts` 为订正记录时间线；`history.ts` 为历史分组、筛选和统计文案；`components/` 为照片、单题帮助、订正记录与历史页视图。HelpRequest/Review 读取使用 `contracts/phase1` 已生成的校验器，没有手写校验，也没有修改共享 contracts 迎合 UI。

`prebuild`/`pretest` 校验构建期生成的 JSON Schema validators。生产运行不使用 Ajv 动态编译，兼容 `script-src 'self'`，无需 unsafe-eval。字体与图标均本地或随包提供，无第三方字体/脚本请求。

本轮完整 `npm test` 通过 79 项（新增 28 项：时间线排序与失效处理、历史分组/筛选/统计文案、重查经操作日志同键重放与防重复、superseded 过滤与替换排序、7 天清理与提示、access_denied/服务端 401 清除与本地过期不清除、blob URL 撤销、页面渲染），TypeScript 严格编译与 Vite 生产 build 通过。新增功能另用本机合成数据的临时 mock 后端在 1024×768 与 390 宽浏览器中走查过历史筛选、继续订正、重查提交、订正记录和清除本机草稿，未连接真实后端或真实学生数据。账号认证测试涵盖强制改密及刷新、账户固定学生绑定、Unicode 密码、会话失效、断网退出、未知改密同键重放、管理员零学生授权与安全错误；原有纠错和订正上下文回归继续执行。
