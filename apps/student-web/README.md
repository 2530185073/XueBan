# 学伴学生网页端 0.2.0

优先交付电脑、横屏平板和手机浏览器中的真实拍照纠错。温纸色与墨绿的作业本界面，核心是自己的学校作业：选图预览 → 明确开始检查 → 原图与逐题初判 → 分级提示 → 新照片订正 → 再检查。没有模型 Key 输入、模拟正确答案、排行榜或额外练习任务。

## 开发与构建

Node.js >= 22.12；React 19.3.1、TypeScript 5.9.3、Vite 8.3.4 与坐班 Web 保持一致，依赖使用 package-lock.json 锁定。

```sh
cd apps/student-web
npm ci
npm run dev
npm test
npm run build
npm run preview
```

开发入口 `http://127.0.0.1:5174/learn/`，`/v1` 代理到 `127.0.0.1:8000`；preview 为 4174。生产构建输出 `dist/`，base 固定 `/learn/`，由项目后端同源提供。`node_modules/`、`dist/`、`*.tsbuildinfo` 不提交。

**实际完整联调优先使用后端 `http://127.0.0.1:8000/learn/`。** 私有图片票据严格同源。若完整上传链路走 Vite 5174，后端 `PUBLIC_BASE_URL` 也必须配置为 `http://127.0.0.1:5174`，使图片 PUT/GET 通过同一代理；不能拿 8000 的票据在 5174 页面跨源上传。不绕过这个限制。

## 使用与数据边界

- 默认使用老师开通的长期账号和密码。学生账户固定绑定后端 `student_id`，没有任意学生 ID 输入或孩子切换入口。换设备、修改密码仍读取同一学生的服务端历史；本地草稿按服务端主体与学生隔离，不擅自合并旧身份的数据。知识图谱尚未实现，本轮不展示虚构图谱或掌握度。
- 登录走 `/v1/auth/login`；会话只写 sessionStorage（token、到期时间和账户会话标记），用户名、密码不写 sessionStorage、localStorage、IndexedDB 或日志。正常刷新先 `/v1/auth/account`，通过服务端认证后才读 `/v1/me` 和该学生草稿。旧配对会话/待交换码不再恢复；旧 `#pair` 片段只清除，不兑换。
- 初始密码必须更换，改密前不调用 `/v1/me` 或读取作业。普通用户也可在顶部“修改密码”操作。新密码按 Unicode 码点计 15–128 字符、UTF-8 不超过 512 字节，保留空格；表单使用 username/current-password/new-password autocomplete。登录/改密/退出均带幂等键，涉及密码的未确认请求只在内存保留原内容和键；刷新后可用新密码重新登录，绝不持久化密码换取自动重放。
- 退出真实调用 `/v1/auth/logout`，无论网络结果均清除本地会话、内存照片和身份。断网时明确提示服务端撤销未确认，不冒称服务端退出成功。已保存的 IndexedDB 草稿仍隔离保留，只有再次通过对应账户授权才可读取。
- 校区管理员从同一登录页进入“学员账号”管理页；允许管理员 `/v1/me` 不含学生授权，不为显示管理页创建假学生，也不调用学生作业接口。管理请求只走 `/v1/admin/`，与作业未知写日志分离。
- 首次选择照片仅创建本地预览，点击“开始检查”才提交模型任务。JPG/PNG 图片入口使用 HTML file input；“用相机拍一张”使用 `capture="environment"`，由手机/平板浏览器提供拍照能力，电脑优先选图。
- 逐题状态区分初判正确、需要订正、识别待核实、无法判断和老师确认；任务完成只代表有可查看结果。照片未读清、无题目、无有效判断均不展示“全部正确”。区域框标注为 AI 推测，不能视为精确错点定位。
- 左栏照片通过当前 Attempt 的 asset IDs 获取 Blob，不把 signed URL 放到 DOM。切换题目后展示对应作答图片；图片加载失败明确提示，不用旧照片替代新作答。Blob URL 在替换/卸载时释放。
- 学生端不直接展开可能含完整答案的 basis。提示由实际按钮请求，实际展示后记录 views；新订正默认报告 unknown，由后端继承真实帮助记录。求助只有服务端成功后才反馈已提交。
- 订正预览“换一张照片”保留 case 和父 Attempt，提交前父 Attempt 变化则要求刷新。完成后优先选中刚订正的题，而不是跳回整页第一题。
- 打开历史、刷新结果只读，不自动发起新的付费检查。当前历史页打开草稿后展示该 case 的最新作答，尚无逐版本作答时间线；原作答、订正父链与帮助证据由后端保留，不能据此声称 UI 已可逐个浏览历史版本。“继续未完成的检查”是独立明确动作。已有草稿使用 core 返回的 draftId，不复制未知请求形成第二条任务链。

## 工程分工与验证

`src/core/` 为契约、身份、IndexedDB、上传和模型任务适配；`useStudentWorkspace.ts` 为 UI 状态协调；`presentation.ts` 为展示和订正上下文规则；`components/` 为照片与单题帮助视图。没有修改共享 contracts 迎合 UI。

`prebuild`/`pretest` 校验构建期生成的 JSON Schema validators。生产运行不使用 Ajv 动态编译，兼容 `script-src 'self'`，无需 unsafe-eval。字体与图标均本地或随包提供，无第三方字体/脚本请求。

本轮完整 `npm test` 通过 51 项（原纠错 core 20、认证 core 10、展示/表单 10、管理员 11），TypeScript 严格编译与 Vite 生产 build 通过。账号认证测试涵盖强制改密及刷新、账户固定学生绑定、Unicode 密码、会话失效、断网退出、未知改密同键重放、管理员零学生授权与安全错误；原有纠错和订正上下文回归继续执行。

本轮已通过实际 Chrome 与本机 PostgreSQL 的账号联调：初始改密、管理员开户、跨学员隔离、密码重置、旧会话撤销、再次登录及历史恢复；逐项比对原7份作业、38次作答及订正关系、9张图片保持不变。390宽度登录页与1440宽度管理/历史页已检查，见 [账号验收记录](../../docs/evidence/accounts-20261017/README.md)。

上一轮已完成浏览器真实普通作业 → 提示 → 新订正流程，并核实数据库中的原作答、父链和 hint_used，也已检查 390/1024/1440 宽度无横向溢出。本轮未重复调用付费模型。Vite 仍提示主 JS chunk 超过 500 kB，后续可按实际性能拆包。更广泛的断网/刷新恢复、手机实机相机与作业准确率仍需继续验收，不能把跑通样例视为完整产品验收。
